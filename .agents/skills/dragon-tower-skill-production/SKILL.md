# Dragon Tower 전투 스킬 제작

1. 저장소 루트의 `docs/STATE.md`, `docs/INDEX.md`부터 읽는다. INDEX에서 결정 기록, 관련 캐릭터 기획·진행, 에셋 파이프라인, 품질 도구와 Windows 체크리스트를 찾는다. 순서 제약은 로드맵과 대조한다. `docs/archive/`는 사용자 지시가 있을 때 읽는다.
2. [제작 표준 및 명세 양식](../../../docs/skill-production.md)을 사용한다. 실제 로더와 렌더 패스를 찾고, 구현 가능한 시안에 레이어와 앵커를 표시한다. 시안 목표, 검수용 적용값과 실측값에 근거를 붙인다. 시전·발사·명중을 각각 어떤 시계와 이벤트로 재생하는지 정한다.
3. 본체와 필요한 앞뒤 RGBA 레이어를 제작한다. 기존 변환·캐시·효과 수명을 재사용한다. 발 기준, 좌우 반전, 실제 적 접촉 좌표, 누락 시 대체 표시를 확인한다. 전투 로직을 변경하면 실제 발동 경로에서 피해·FX 횟수와 만료, 장착·저장 회귀를 확인한다.
4. 게임·프리뷰 빌드, CTest, 에셋 검사와 문서 검사를 실행한다. 시안과 게임을 동일 배율·기준점으로 정규화하고 이벤트나 프레임을 맞춰 비교한다. 결함이 보이면 개별 레이어·합성·이벤트를 확인하고 해당 부분을 수정한 뒤 같은 조건과 주변 케이스를 다시 캡처한다. 실전 Windows 항목은 직접 확인한 범위를 표시한다.
5. 요청 범위에 따라 명세, 게임용 에셋과 코드, 빌드·테스트 로그, 시안/게임과 수정 전후 대조표, 미검증 목록을 남긴다. 필요한 문서와 진행 기록을 연결하고 기준 커밋·작업 브랜치·열린 PR을 보고한다.

## 멈추고 확인할 조건

- 선행 검수나 팀 소스 담당 순서와 충돌하면 영향과 근거를 먼저 알린다. 새 동작 종류 또는 확정 규칙을 바꾸는 작업은 기존 승인 범위를 확인한다.
- 원본이나 사용 권한이 없어 시안을 확정할 수 없으면 필요한 참조만 요청한다. 문서 조사와 권한이 확인된 부분의 검수는 이어간다.
- Windows 실전이나 기준 시안을 확보할 수 없으면 해당 항목을 미검증으로 남기고 재현 조건을 기록한다. 빌드·자동 검사·프리뷰 결과는 각각 근거와 함께 보고한다.

## 저장소 안전

- 별도 브랜치에서 작업하고 기존 에셋·사용자 변경과 저장 인덱스를 보존한다. 사용 권한이 확인된 에셋만 반영한다.
- 효과의 클릭 통과, 게임 규칙, 기존 스킬의 동작을 저장소 지침에 맞춰 확인한다.
- main 직접 커밋, 강제 푸시, 승인 없는 병합을 금지한다. 승인된 작업 브랜치에만 푸시하고 PR과 CI 결과를 확인한다.
