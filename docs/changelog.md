# 버전별 바뀐 점

버전은 "밖에서 보이는 변화"를 기준으로 올린다. 저장 파일 형식이 바뀌면 호환 여부를 반드시 적는다.

## 이슈 #47~#50 수정 (2026-11-16)

Windows에서 직접 실행하며 찾은 네 가지다. 함께 **바탕화면 사냥 방식을 정정**했다 — 탑 100층 설계안에 적었던 "클릭 사냥으로 교체"는 취소하고 **디펜스를 유지**한다(사용자 정정). 기획서 10장·설계안·CLAUDE.md 를 같이 고쳤다.

- **#47 "아래쪽에만"을 꺼도 전투를 시작하면 아래로 고정되던 것.** 사용자 결정으로 규칙을 바꿨다 — 싸우는 자리는 이 설정을 따른다. 켜면 맨 아래 띠, 끄면 화면 전체에서 싸우고 적은 왼쪽 밖에서 드래곤이 있는 높이 근처로 들어온다. 사냥 중에 바꿔도 바로 적용된다. 자동 사냥은 전부터 띠로 내려가지 않고 있었는데(시작 경로가 달랐다) 이제 같은 규칙을 쓴다(`Game::enterBattleArea`).
- **#48 전투를 시작하면 화면 전체가 살짝 어두워지던 것.** 키보드를 받는 동안 화면 전체를 칠하던 표시를 없앴다. 바탕화면 전투(직접·스킬 수동)를 시작하면 키보드가 저절로 켜져 필터처럼 보였다.
- **#49 아래쪽에서 드래곤·적이 작업 표시줄 밑으로 잘리던 것.** 띠 위치는 맞았는데 **그림을 판정 원의 가운데에 두어** 발이 원보다 아래(드래곤은 약 11px, 캐릭터 크기 2배면 약 56px)로 내려갔다. 이제 시트의 발(240/256 줄)을 판정 원의 아래 끝에 맞춘다. **판정·이동은 바뀌지 않고 그림이 발 기준으로 선다** — 그래서 캐릭터를 크게 키우면 위로 자란다.
- **#50 관리창·스킬창을 열면 프레임이 떨어지던 것.** 큰 창틀 그림(원본 1109×1382)을 매 프레임 9조각으로 줄여 그리던 비용으로 본다. 같은 크기·투명도로 한 번 합성해 두고 다시 붙인다(`Renderer::cachedPiece`). **측정은 하지 않았다** — 트레이의 프레임 측정(#51)으로 전후를 재 보면 확실해진다.

### 저장 파일

- 바뀌지 않았다.

### 사람이 확인할 것

1. "아래쪽에만"을 끄고 전투를 켜면 드래곤이 제자리에서 싸우고 적이 그 높이로 오는지.
2. 전투를 켜도 화면이 어두워지지 않는지.
3. 아래쪽에 있을 때 드래곤 발과 적이 작업 표시줄 위에 보이는지(캐릭터 크기 1배·2배). 상태창·메뉴의 그림 틀이 전과 같은지.
4. 관리창·스킬창을 열어도 드래곤이 부드럽게 움직이는지.

## 탑 100층 T1: 층 규칙과 레벨 상한 (2026-11-15)

사용자가 정한 탑 100층 확장의 첫 단계다. 확정 사항은 [기획서 10장](game-design.md#확정-탑-100층-확장-방향-2026-11-15), 설계와 다음 단계는 [`docs/tower-100-design.md`](tower-100-design.md).
**지금 탑(`floors.txt` 10층)과 바탕화면 사냥은 바뀌지 않는다.**

- `core/Tower.h` 에 층 구조 규칙을 더했다 — `floorType`(10의 배수 필드 보스, 그 외 5의 배수 중간 보스), `huntFloorFor`(직전 일반 층, 보스층 건너뜀), `fieldBossLevelCap`(층 × 5), `partyMeetsLevelCap`(출전 4마리 각각 상한 이하). **아직 게임 흐름에 연결하지 않았다**(T3·T4·T7).
- 최고 레벨 30 → **500**. 경험치 곡선은 그대로(미결정)이고, 1→500 누적(약 4.2억)이 32비트 정수 안에 있는지 테스트가 감시한다.
- `kMaxSkillsPerDragon` 은 최고 레벨과 같은 값을 쓰고 있었다. 500으로 같이 늘지 않게 **30으로 따로 고정**했다(동작 변화 없음).
- `floors.txt` 상한: 층 50 → 100, 적 레벨 99 → 500.

### 저장 파일

- 형식은 그대로다. 읽을 때 레벨을 자르는 상한만 30 → 500이 됐다. **새 빌드로 31 이상 올린 드래곤을 이전 빌드로 열면 30으로 잘린다.**

### 사람이 확인할 것

- 레벨 30에 멈춰 있던 드래곤이 다시 경험치를 얻는다. 상태창의 "최고 레벨" 표시는 이제 500에서만 나온다.
## win: 스킬 효과를 스프라이트로 그린다 (2026-11-15)

**화면은 아직 달라지지 않는다.** `fx=` 를 적은 스킬이 아직 하나도 없기 때문이다(자동 큐 8번).
v1.6이 코어에 만들어 둔 세 단계(`Fx::phase`)와 설정(`fx_*`)을 **그리는 쪽에 연결한 것**이다.
`fx_<이름>.png` 를 넣고 `dragon.txt` 에 `fx=` 를 적는 순간 보이기 시작한다.

- `Sprites::loadFxSheets`/`fxSheet` — `assets/dragons/<키>/fx_<이름>.png` 를 읽는다. 규칙은
  `skill_*.png` 와 같다(가로 한 줄, `fx_frame_w`, 여러 스킬이 같은 이름을 쓰면 한 번만 읽는다).
  **파일이 없으면 조용히 넘어가고 예전처럼 도형으로 그려진다** — 깨진 그림이 나오지 않는다.
- `Renderer::drawFxSheet` — 시트가 있으면 그것으로 그리고, 없으면 `false` 를 돌려줘 기존 도형
  분기로 내려간다. 되돌릴 자리를 그대로 남겼다.
- **앞·뒤 층**: `drawWorld` 가 `drawFx` 를 두 번 부른다 — 적을 그린 뒤 `inFront=false`(본체 뒤),
  발사체 뒤 `inFront=true`(본체 위, **지금까지 부르던 그 자리**). `Fx::inFront` 기본값이 `true`
  이므로 기존 효과는 전부 예전 자리에 그대로 그려진다.
- **크기·위치**: 기준 높이는 **드래곤 본체와 같다**(`kDragonRadius * 3 * 보기 크기`). 거기에
  `fx_scale` 과 `fx_render_scale` 을 곱하고, 중심은 효과가 터진 지점 + `fx_offset_y` 다.
  좌우는 뒤집지 않는다.
- **세 단계 보이기**: 발동 0.55→1배로 커지며 또렷해지고, 지속 1배, 잔류 1→1.18배로 퍼지며 사라진다.
  시간을 직접 나누지 않고 `Fx::phase()`·`Fx::phaseProgress()` 만 쓴다.
- **`Zone`·`Projectile` 은 그대로 두었다**(항목이 "정하라"고 한 것). 지속이 긴 장판에 세 단계를
  억지로 맞추지 않는다 — `implementation-notes.md` 에 근거와 되돌리는 법을 적었다.

## 데이터: 탑 10층 구성 (2026-11-15)

**코드는 바뀌지 않았다.** `assets/tower/floors.txt` 를 새로 넣어 탑을 3층 → **10층**으로 늘렸다
(자동 큐 3번). 1번(층 데이터화, PR #24)이 만든 파서를 처음으로 실제 데이터로 쓴 것이다.
적은 지금 있는 7종만 쓰고 새로 만들지 않았다. **파일을 지우면 즉시 3층으로 돌아간다.**

- **1~3층은 내장 기본값과 한 글자도 다르지 않다.** 지금까지의 체감을 건드리지 않기 위해 그대로 옮겼다.
- 보스는 **3·6·9층**(3층마다)이고 **10층은 탑의 주인**이다. 6·9층은 정예 리치, 10층은 리치를 쓴다
  (`elite-lich` 파일이 "중간 층 보스 자리"로, `lich` 가 "탑의 주인"으로 적혀 있는 대로다).
- 층마다 **무엇으로 어려워지는가**를 돌려 가며 올렸다 — 사거리(4층) → 수(5층) → 2페이즈(6층) →
  무게+사거리(7층) → 속도(8층) → 2페이즈+호위(9층) → 2페이즈+사거리(10층). 레벨만 오르는
  곡선을 피하려는 것이다.
- **난이도 곡선을 숫자로 고정했다.** 층을 하나만 담은 `floors.txt` 로 "온전한 체력에서 그 층만"
  재서(망령룡 Lv8 스킬 수동, 시드 900, 40회) **4층부터 10층까지 단조 증가**하게 맞췄다 —
  4.4% → 10.7% → 17.7% → 20.2% → 40.0% → 43.2% → 62.2%. **10층(62.2%)이 탑에서 가장 어렵다.**
- **전체 등반(10층까지) 전멸은 없다.** 망령룡 Lv8 97.5% · Lv10 100%, 그림자룡 Lv8 27.5% · Lv10 62.5%
  (스킬 수동 40회). 직접 조작 봇은 전 레벨 100%다(봇이 예고를 전부 피하므로 사람 기준이 아니다).
- **3층만 곡선 위로 튀어나온다**(54.2%, 4~9층보다 높다). 3층 보스가 "3층 탑의 최종 보스"로
  맞춰진 수치여서다. 1~3층을 건드리지 않기로 했으므로 그대로 두고, 바로잡는 것은 14번
  (층별 보상·난이도 곡선)으로 넘긴다 — `implementation-notes.md` 에 측정값과 함께 적었다.
- `kTowerFloorHeal`(0.30)·`kTowerClearExp`·"탑에서는 자동 사냥 불가"는 **건드리지 않았다.**

## 문서: 깊이감 축 C — 자동 사냥의 결정과 위험 설계안 (2026-11-15)

**코드·게임 데이터는 바뀌지 않았다.** 자동 사냥에 결정을 넣는 두 갈래 — (가) 위험 없이
사냥터를 고르게 하기 / (나) 실제로 위험을 올리기 — 를 "얻는 것 / 잃는 것 / 재는 방법"으로
[`docs/design-depth-auto-hunt.md`](design-depth-auto-hunt.md) 에 나란히 적었다 (자동 큐 18번).
**선택은 사람이 한다.**

- **위험이 0인 까닭을 기계장치까지 내려가 쟀다.** 경계는 **드래곤 속도 175**다. 적이 그보다
  느리면 예고(0.85초) 동안 드래곤이 뒷걸음질해 장판이 뒤에 떨어진다. 적 사거리를 72 → 200으로
  올려도 **피해가 0.00배로 그대로**이고, 속도를 180(드래곤 +5)으로 올리면 1.26배가 된다.
  → "적을 멀리서 때리게 한다"는 길은 듣지 않는다.
- **가장 중요한 발견: 속도를 260까지 올려도 사망이 0/20이다.** 받은 피해 1.93배인데 회복이
  3.12배다 — 파도 사이 휴식 15초 × 1.5%/초로 한 파도에 최대 22.5%가 차서 깎임이 누적되지 않는다.
  **적 구성·속도·파도만 건드리는 (나)안은 효과가 없다.** 회복 쪽을 함께 건드려야 한다.
- 기존 기록("Lv1·5·10에서 피해 0.00배")에 덧붙였다: **고레벨에서는 0을 조금 벗어난다**
  (Lv20 시작 0.01배 · Lv28 시작 0.09배). 적 속도는 레벨마다 +2.0~3.5이고 드래곤은 175 고정이라
  **적 레벨 24쯤에서 넘어선다**(95 + 3.5 × 23 = 175.5). 다만 3시간에 0.09배는 위험이 아니다.
- **핵심 질문("(가)만 골라도 깊이감이 생기는가")에 답했다: 생긴다 — 조건 하나가 붙는다.**
  선택이 그 런 동안 되돌릴 수 없고 결과가 **탑에서** 보여야 한다. 자동 사냥의 산출물은 레벨이고
  레벨이 쓰이는 곳은 영구 사망이 실제로 작동하는 탑이므로, 사냥터 선택은 위험을 없애는 것이
  아니라 **자동 사냥에서 탑으로 옮기는** 것이다.
- **경고·중단·알림은 새로 만들 것이 없다.** `Screen::AutoWarning`(시작 전 경고),
  `stopHunt(reason)`(경험치 상한이 이미 쓰는 길), `alert` → 트레이 풍선(소리 없음)이 다 있다.
- `cfg::kAutoExpCapEnabled`·탑에서 자동 사냥 불가·맨 아래 띠·예고 후 판정은 **건드리지 않았다.**

## 문서: 깊이감 축 B — 탑 진입 변주 설계안 (2026-11-15)

**코드·게임 데이터는 바뀌지 않았다.** 탑에 들어갈 때 고르는 축복/저주를 어디에 어떻게 적을지,
변주 예시 8개와 데이터 파일 형식 초안·되돌릴 스위치·재는 방법을
[`docs/design-depth-variations.md`](design-depth-variations.md) 에 적었다 (자동 큐 17번).
**선택은 사람이 한다.**

- 큐 17번이 정하라고 한 자리(**저주를 둘지**)를 정했다: **둔다. 단 "교환형"으로만** — 모든 변주에
  오르는 것 하나와 내려가는 것 하나가 **둘 다** 있어야 한다(순수 축복·순수 저주 금지). 축복만 두면
  고르는 일이 "제일 센 것 고르기"가 되어 결정이 사라지고, 런이 달라지는 대신 쉬워지기만 한다.
- 체감 난이도가 바뀌는 자리라 **허용 한계를 숫자가 아니라 규칙 7개(R1~R7)로** 적었다. 핵심은
  **R1 한 등반에 변주는 하나만**(조합 폭발을 없앤다)과 **R4 권장 레벨 8에서 1층 적의 한 대가
  최대 체력의 1/3을 넘지 않는다**(임시값이 바뀌어도 기준이 남는다).
- **새 파서를 만들지 않는다**는 것을 코드로 확인했다 — `parseEnemyText` 는 돌려주는 형이 달라
  그대로 쓸 수 없지만, PR #24의 `parseTowerText` 가 `DragonData.cpp` 안에서 `trim`·`stripComment`·
  `lower` 를 쓴 선례가 있다. 재사용하는 것은 **파서가 아니라 형식과 보조 함수**다.
- 고르는 화면도 새로 만들지 않는다 — `Screen::TowerWarning` 이 **이미 모드를 고르는 자리**다.
  변주는 **탑 진입 전 한 번**만 고르고, 들어가기 전까지는 다시 고를 수 있다. 층마다 고르게 하면
  R1을 포기해야 해서 1차에서는 하지 않는다.
- **저장 형식은 건드리지 않는다.** 변주는 한 등반 동안만 걸려서 1차에는 저장할 것이 없다.
- 적을 수 없어 **선택지로도 적지 않은 것**: 예고 시간을 줄이는 변주(확정 규칙 위반),
  자동 사냥에 영향을 주는 변주(탑에서 자동 사냥 불가), `cfg::kAutoExpCapEnabled` 를 건드리는 변주.

## 문서: 깊이감 축 A — 사망 계승(해금) 설계안 (2026-11-15)

**코드·게임 데이터는 바뀌지 않았다.** 죽어도 남는 재료(`bestFloor`·`towerClears`·`codex`·`grave=`)가
지금은 **보여 주기만** 하는 것을 코드 자리까지 확인하고, 계승 세 안 (가) 변주만 / (나) 힘+안전장치 /
(다) 그대로 두기 를 [`docs/design-depth-legacy.md`](design-depth-legacy.md) 에 표로 비교했다
(자동 큐 16번). **선택은 사람이 한다.**

- **새 저장 키 없이 시작할 수 있다**는 것을 파서로 확인했다 — `grave=` 는 `parts.size() >= 4` 로
  읽어 필드를 더해도 옛 빌드가 무시하고(`SaveData.cpp:256`), 모르는 키는 조용히 넘어간다. 즉
  **호환이 깨지지 않는다.**
- 권하는 안은 **(가) 변주만**, 그 안에서 **A3(묘비 유산 = 장착 프리셋)** 부터. A2(탑 지름길)는
  1·2층에서 잃는 체력이 0.0% 라 **난이도를 전혀 바꾸지 않고 시간만** 줄여 깊이감으로 가장 약하다.
- A1(스킬 후보 고르기)은 **큐 13번이 남긴 사람 결정**(빈 칸 자동 채움 순서)에 먼저 걸린다.
- 적을 수 없어 **선택지로도 적지 않은 것**: 묘비 소모 부활·레벨 계승 — 개체 부활과 구분이 흐려져
  확정 규칙 위반이다.

## 수정: assets 를 못 찾으면 이유를 알려 준다 (2026-11-15)

**증상**: 배포본을 받아 실행했는데 **망령룡·그림자룡이 하나도 없었다.**

**원인**: 받은 압축에 `assets` 폴더가 없었다(실행 파일만 들어 있는 아티팩트였다).
v1.5에서 내장 4종을 지운 뒤로 종은 전부 `assets/dragons/` 에서 오기 때문에 종이 0마리가 된다.
**그런데 화면에 아무 말도 안 나왔다** — `loadDragonFolders` 는 폴더가 아예 없으면 경고도 없이
돌아오고(`warnings` 가 빈다) `newSpecies` 도 0이라, 데이터 오류를 알리는 기존 알림이 하나도
뜨지 않았다. 사용자에게는 "드래곤이 사라진" 것으로 보인다.

**고친 것**
- `App::init` 이 `speciesCount() == 0` 을 따로 확인하고, `assets/dragons` 폴더가 없으면
  **무엇이 문제이고 어떻게 고치는지** 화면에 띄운다(600초 — 사실상 계속 보인다).
  폴더는 있는데 종을 못 읽은 경우는 다른 문구를 쓴다.
- 그 아티팩트 자체는 **팀원이 PR #46 에서 고쳤다** — `dragon-tower-mingw-play` 로 이름을 바꾸고
  `assets` 를 함께 담아 받아서 바로 켤 수 있게 했다. 이 PR 에서는 워크플로를 건드리지 않는다
  (처음에는 아티팩트를 없애려 했는데 #46 쪽이 낫다 — MSVC 빌드를 기다리지 않고 켜 볼 수 있다).
- 다만 **아티팩트를 고쳐도 이 화면 경고는 필요하다.** `exe` 만 다른 곳으로 옮기면 같은 일이
  또 생기고, 그때 이유를 알려 주는 것이 이 수정이다.
- 주의: 이제 플레이할 수 있는 배포본이 둘이다 — `build.yml` 의 `DragonTower-windows`(MSVC, 정식)와
  `quality.yml` 의 `dragon-tower-mingw-play`(mingw, 빠른 확인용). **버그를 제보할 때는 어느 쪽인지 적는다.**

**교훈**: 데이터가 없을 때 **조용히 비는 것**이 가장 나쁘다. 잘못된 값은 경고가 나오는데
없는 폴더는 아무 말도 안 나왔다. 앞으로 "없으면 그냥 돌아온다"를 쓸 때는 부르는 쪽이
그 사실을 사용자에게 전달하는지 같이 확인한다.

## 수정: 새니타이저·퍼저·정적 분석이 찾은 것 셋 (2026-11-14)

기능은 더하지 않았다. **게임이 죽거나 값이 조용히 달라지던 자리 셋**을 고치고 회귀 테스트를 붙였다.
찾은 방법과 도구는 [`docs/quality-tools.md`](quality-tools.md).

- **보스 2페이즈 소환에서 해제된 메모리를 읽었다** (`World::updateEnemies`).
  `spawnEnemy` 가 `enemies_` 를 재할당하는데 소환 좌표로 쓰는 `e.pos` 를 **루프 안에서 다시 읽고**
  있었다. 2마리 이상 소환하는 적에서 두 번째부터 엉뚱한 좌표가 나올 수 있었다(값에 따라서는
  그럴듯해 보여 1417건의 테스트가 전부 통과했다). 기준점을 루프 **앞에서** 복사한다.
  → 지금 데이터에서 2페이즈·소환을 함께 쓰는 적은 리치뿐이다.
- **종이 하나도 없으면 저장 파일을 읽는 순간 죽었다** (`speciesDef`).
  v1.5에서 내장 4종을 지운 뒤로 레지스트리가 **비어 있을 수 있다**(`assets/dragons` 가 없거나
  전부 읽기에 실패). 그때 `std::clamp(x, 0, -1)` 이 되어 빈 컨테이너를 인덱싱했다.
  `serializeSave` 가 묘비·현재 개체마다 이 함수를 부르므로 **에셋이 사라지면 켜자마자 죽는**
  경로였다. 이제 "알 수 없는 종"으로 물러선다.
  → **저장 파일 형식은 바뀌지 않았다.** 기존 저장 파일은 그대로 읽힌다.
- **저장 파일의 레벨 상한이 한쪽에만 있었다** (`deserializeSave`).
  `stable.N.level` 은 30으로 자르는데 `dragon.level` 만 자르지 않았다. 손으로 고친 저장 파일이
  레벨 34로 읽히고 그대로 저장됐다가 **다음에 켤 때 30으로 잘렸다.** 두 자리가 같은 규칙을 쓴다.
  → 레벨 30을 넘는 저장 파일은 이제 읽을 때 30이 된다. 정상적으로 플레이한 저장 파일에는 영향이 없다.

함께 고친 것

- `core_tests.cpp` 의 스킬 장착 검사 한 줄이 **무엇을 넣어도 통과**하고 있었다
  (`slots[0] != before || before == slots[0]` — 항상 참이고, 게다가 `before` 가 비교 대상이 아닌
  2번 칸의 값이었다). 두 칸을 각각 붙들게 고쳤다. 일부러 회귀를 넣어 잡히는 것을 확인했다.
- `Sprites.cpp` 의 주석 자르기에서 임시 문자열을 만들던 것(`substr` → `erase`).

## v1.6 — 탑 층을 데이터로 (2026-11-14)

탑이 `Game::spawnTowerFloor` 에 **3층까지 하드코딩**돼 있었다. 드래곤(v0.2)과 적(v0.4)은 이미
폴더·레지스트리로 뺐는데 탑만 코드에 남아, 층을 늘리는 모든 작업이 여기서 막혔다.

### 추가

- **`assets/tower/floors.txt` 로 탑 층을 정한다.** 코드를 고치지 않고 층을 늘리거나 적 구성을
  바꿀 수 있다. `키=값` + `[floor.N]` 형식으로 `dragon.txt`·`enemy.txt` 와 같다
  ([사용법](../assets/tower/README.md)).
  ```
  [floor.2]
  title=2층
  spacing=160            ; 옆 적과의 세로 간격
  enemy=goblin x1 lv6
  enemy=ogre x1 lv6 inset=60
  ```
- **키 자리의 `-` 는 "이 층의 기본 적"** 이다. 보스 층이면 보스가 선다.
- **보스를 아래 층에도 놓을 수 있다.** v1.5까지는 1·2층에 일반 적만 놓을 수 있었다.

## v1.6 — 적 변종: 그림을 빌려 쓰기 (2026-11-14)

## v1.5 — 모션 고르기, 적 방향, 아이콘, 내장 종 삭제 (2026-11-14)

### 추가

- **드래곤을 오른쪽 클릭하면 모션 목록이 뜬다.** 고르면 **다음 입력까지** 그 모션을 유지한다. 그림이 있는 모션만 보여 준다(없는 모션은 대체 그림이 나와 헷갈린다). "자동으로 되돌리기"로 풀 수 있고, 키를 누르거나 드래곤이 아닌 곳을 누르면 자동으로 풀린다.
- **끌어 옮겨도 고른 모션은 유지된다.** 자동 행동일 때만 놓은 자리에서 새 행동을 고른다.
- **스킬 아이콘.** `assets/dragons/<키>/icon_1.png` ~ `icon_7.png`. 망령룡·그림자룡 각 7개를 넣었다. 없으면 전처럼 이름 첫 글자로 그린다.

### 고침

- **적의 좌우가 반대였다.** 적 그림은 왼쪽을 보고 그려져 있는데 드래곤(오른쪽 기준)과 같은 규칙을 썼다. `enemy.txt` 의 `art_facing=left|right` 로 정하며 기본은 `left` 다.
- **맞았을 때 번쩍임이 너무 밝았다.** 드래곤 0.6 → 0.25, 적 0.7 → 0.3.
- **망령룡 쉬기 모션이 너무 컸다.** `render_scale` 1.50 → **1.14**. 대기와 같은 부위(청록 흉곽 발광부)의 **넓이**로 다시 쟀다 — 대기 1537px, 쉬기 1185px 이므로 `sqrt(1537/1185) = 1.14`. 전에는 "가장 두꺼운 열"로 쟀는데 엎드린 자세에서는 그 값이 과장된다.
- **관리창·스킬창·선택창을 열어도 바탕화면 전투가 멈추지 않는다.** 창이 떠 있어도 키보드는 그대로 들어오므로 직접 조작도 이어진다. 보이지 않거나(전체화면) 창이 활성화되지 않은 경우에는 전처럼 멈춘다 — 손을 쓸 수 없는데 맞기만 하는 상황을 막기 위해서다.
- 빈 스킬 칸의 `＋` 가 폰트에 없어 깨져 보이던 것을 평범한 `+` 로 바꿨다.

### 지운 것

- **내장 드래곤 4종(화염·대지·바람·물)을 모두 지웠다.** 코드의 내장 정의와 `assets/dragons/{fire,earth,water,wind}` 폴더를 함께 지웠다. 이제 종은 **전부 `assets/dragons/<키>/` 폴더에서** 온다(남은 종: 망령룡, 그림자룡).
- `Species::Fire` 같은 이름은 "레지스트리의 몇 번째"라는 **번호**로만 남는다. 특정 종을 가리키지 않는다.
- 테스트는 시작할 때 시험용 종 네 개(`testa`~`testd`)를 등록해서 돈다.

### 저장 파일 주의

**지운 4종으로 키우던 드래곤이 있으면 불러올 수 없다.** 저장 파일에 `fire` 같은 키가 남아 있어도 그런 종이 더 이상 없기 때문이다. 망령룡·그림자룡으로 키운 개체는 그대로 이어진다.

## v1.4 — UI 정리와 노트북 프레임 (2026-11-14)

### 프레임

노트북에서 프레임이 떨어진다는 이야기를 듣고 그리는 경로를 살폈다. **창 모드로 바꾸지 않고** 다음 둘을 고쳤다.

- **고품질 바이큐빅 보간 → 양선형.** 스프라이트와 UI 조각을 매 프레임 다시 샘플링하는데, 바이큐빅은 그때마다 훨씬 비싸다. 눈으로는 거의 차이가 없다.
- **설정 버튼 창을 통째로 없앴다.** 레이어드 창 하나와 매 프레임 `UpdateLayeredWindow` 한 번이 사라진다.

아직 남은 비용은 **화면 전체 크기의 면을 매 프레임 지우고 합성하는 것**이다(1920×1080이면 초당 6천만 픽셀). 더 줄이려면 그린 부분만 갱신하거나 그린 조각을 캐시해야 한다. 먼저 이번 것으로 얼마나 나아지는지 재 보기로 했다.

### 바뀜

- **설정(입력) 버튼을 없앴다.** 키보드는 게임이 알아서 받는다 — **싸우는 중이고 자동 모드가 아닐 때만.** 그때만 창을 활성화하므로 평소에는 쓰던 프로그램의 포커스를 뺏지 않는다. 마우스는 전처럼 우리가 그린 것 위에서 항상 받는다.
- **깨져 보이던 글자를 고쳤다.** 상태창의 `▦`·`≡` 와 메뉴의 `－`·`＋` 는 폰트에 없어서 네모나 토글 스위치처럼 보였다. "관리"·"메뉴"·"닫기" 같은 한글로 바꿨다.
- **메뉴를 전투 설정 / 환경 설정 두 탭으로 나눴다.**
  - 전투 설정: 사냥 시작·중단, 사냥 모드, 유지 간격, 탑 도전, 기록·도감
  - 환경 설정: 캐릭터 크기, 아래쪽에만, 절전, 드래곤 관리, 종료
- **메뉴 크기는 오른쪽 아래 모서리를 끌어서** 바꾼다. 위쪽의 －/＋ 버튼은 없애고 그 자리에 **닫기**를 뒀다.
- **캐릭터 크기를 슬라이더로** 바꿨다.
- `Ctrl+Shift+D` 와 트레이 메뉴는 이제 **메뉴를 열고 닫는다**(키보드 받기는 자동이라 켤 일이 없다).

### 저장 파일

- `ui.menuTab` 이 추가됐다. 이전 저장 파일은 기본값(전투 설정)으로 읽힌다.
## v1.4 — 스킬 해제와 장착 (2026-11-14)

PR #6(망령룡 스킬 기획)이 "액티브 4종·패시브를 현재 3슬롯에 직접 대응시킬 수 없다. 장착/확장 여부
미정"이라고 남겨 둔 결정을 정하고 구현했다.

### 정한 것

- **레벨마다 스킬 하나씩 해제.** `dragon.txt`에 `level=`을 적으면 그 레벨, 적지 않으면 아직 비어 있는
  가장 낮은 레벨이 목록 순서대로 배정된다. 스킬을 뒤에 더하기만 하면 다음 레벨에 자동으로 붙는다.
- **액티브는 4칸까지 장착해서 쓴다.** 조작키 1~4가 곧 칸이고, **자동 전투도 장착한 것만** 쓴다
  (칸 순서가 우선순위). 해제만 되고 빼 둔 스킬은 "바깥 간격" 계산에도 들어가지 않는다.
- **패시브는 칸을 쓰지 않는다.** 해제되면 항상 적용된다. `PassiveStat`(능력치 상시 보정)과
  `PassiveOnKill`(처치 시 회복) 두 종류를 더했다.
- **장착 변경은 전투·탑 밖에서만.** 드래곤 교체와 같은 규칙이다(불리할 때 바꿔 끼워 위험을 피하지 못하게).
  탑에서는 창 자체가 열리지 않는다 — 창이 떠 있는 동안 전투가 멈추므로 시간 벌기가 된다.

### 추가

- **스킬 관리창.** 상태창의 "스킬" 버튼이나 메뉴의 "스킬 관리"로 연다. 칸을 고르고 스킬을 누르면
  들어간다. 이미 다른 칸에 있으면 맞바꾼다. 쓰지 않고 남은 스킬이 있으면 버튼에 `●`이 붙는다.
- **스킬별 본체 모션.** `dragon.txt`의 `motion=` 한 줄로 `skill_<이름>.png`를 재생한다.
  시트가 없으면 공용 `attack`으로 그려지므로, 데이터만 먼저 넣고 그림은 나중에 넣어도 된다.
- **망령룡 `attack.png`** — 그동안 없어서 대기 모션으로 때우고 있었다. 원거리 기본 공격(망령탄)
  모션이 들어갔다. 스킬 본체 모션 4종(망자의 발톱·혼령 관통·망령의 침식·영혼 수확)도 함께 변환했다.
  다섯 장을 한 번에 변환해 공통 배율을 쓰고, 기존 대기와 몸 크기를 맞추려고 `render_scale=1.04`를 뒀다
  (흉부 영혼 코어 높이 대기 136px : 새 패키지 130px. 눈으로도 확인했다).
- **그림자룡 스킬 본체 모션 3종** — 발톱·숨결·보호막. 기존 다섯 장과 **같은 명령에 넣어** 다시
  변환했고 결과가 바이트 단위로 같은 것을 확인했다(공통 배율 0.7278 유지).
- 그림자룡에 **어둠의 숨결**(Line)과 **그림자 걸음**(회피 +4%p 패시브), 망령룡에 **망자의 발톱**·
  **혼령 관통**·**망령의 침식**·**영혼 수확**(패시브)을 더했다. **수치는 전부 임시값이다.**
- `asset_check`가 스킬별 해제 레벨·종류·모션 파일 유무를 적고, **한 레벨에 스킬이 둘 이상 열리면 경고**한다.

### 고친 것

- **다친 드래곤의 체력이 저장되지 않던 문제**(v1.3부터). 불러올 때 현재 개체를 보유 목록에서
  복원하는데 `snapshotForSave`가 목록 쪽에 체력을 적지 않아, 다시 켜면 체력이 가득 찬 채로 돌아왔다.
  영구 사망의 위험을 약하게 만드는 문제라 이번에 함께 고쳤다(`testActiveDragonHpSaved`).

### 저장 파일

- `dragon.slots` / `stable.<번호>.slots` 가 추가됐다(`0,2,-1,5` 형식).
- 이전 저장 파일은 **해제된 액티브로 칸이 자동으로 채워져** 그대로 이어진다.
- 저장된 칸이 그 종·레벨에 맞지 않으면(스킬 목록이 바뀐 경우 등) 그 칸만 비우고 다시 채운다.

### 아직 안 한 것

- **효과(FX) 그림.** 발톱 궤적·숨결·보호막·낙인 같은 효과 전용 스프라이트를 그리는 코드가 없다.
  이번에는 **본체 모션까지만** 넣었다. 그림은 `assets/references/` 에 함께 넣어 두었다.
- 그림자룡 궁극기(영야의 날개)는 충전 루프만 있고 본체·폭발 그림이 아직 없다.
- 망령룡 `skill_harvest.png`는 변환해 두었지만 패시브는 발동 모션이 없어 아직 쓰이지 않는다.

## v1.3 — 드래곤 관리창과 교체 (2026-11-14)

기획서에서 "정하지 않으면 영구 사망 규칙이 이름만 남는다"고 적어 둔 항목을 정하고 구현했다.
정한 내용은 [통합 기획서의 확정 절](game-design.md#확정-여러-드래곤-보유와-교체-2026-11-14-v13)에 있다.

### 추가

- **드래곤 관리창.** 상태창의 `▦` 버튼이나 메뉴의 "드래곤 관리"로 연다. 보유 목록(최대 4마리), 각 개체의 체력·레벨, 묘비 기록을 한 화면에서 본다.
- **바탕화면에 표시 = 플레이할 드래곤.** 관리창에서 "바탕화면에 표시"를 누르면 그 드래곤으로 바뀐다. 둘을 따로 두지 않는다.
- **여러 마리 보유** (최대 4). 관리창의 빈 자리에서 "새 드래곤"으로 언제든 데려온다.
- **보관 중 체력 회복** — 1초에 최대 체력의 2%(0에서 꽉 차기까지 50초). **경험치는 오르지 않는다.**

### 지켜진 규칙

## v1.1 — UI 그림 맞춤 방식 고침 (2026-11-14)

v0.9에서 넣은 UI 그림이 실제 화면에서 깨져 보였다. 에셋을 만든 쪽에서 받은 사용 가이드를 반영했다.

### 무엇이 잘못됐나

**1109×1382짜리 큰 장식 창틀을 270px 상태창에 9조각으로 넣었다.** 테두리 합(240×280)이
목적지와 비슷해서 가운데가 거의 0이 되고, 장식만 남아 글자·버튼을 덮었다. 버튼도 세로로
눌려(원본 106px → 목적지 42px) 비율이 깨졌다.

### 바뀜

- **조각마다 맞추는 방식(`fit`)을 ui.txt 에서 고른다.**
  - `nine` — 9조각(큰 창틀). 테두리가 목적지의 35%를 넘지 않게 **가로·세로 같은 배율로** 줄인다. 전에는 축마다 따로 줄여서 모서리가 찌그러졌다. 원본의 55% 미만으로 줄여야 하면 **그림을 포기하고 도형으로 그린다.**
  - `height` — 높이에 맞춰 통째로 줄이고 가로만 늘린다. **세로 눌림이 사라진다.** 버튼·막대에 쓴다.
  - `contain` — 비율을 지킨 채 넣는다. 토글·체크에 쓴다.
- **버튼 글자는 테두리 안쪽에만 놓인다.** 밝은 뼈 장식 위에 글자가 올라가지 않는다.

- 그 결과 **상태창·메뉴는 도형으로, 그 안의 버튼·막대·토글은 그림으로** 그려진다. 큰 창틀은 선택 화면·모달처럼 큰 창에서만 쓰인다.

### 지운 것

- `assets/ui/default/title.png` — 한 장에 버튼 상태 3개가 들어 있어 조각으로 쓸 수 없다. `assets/references/ui/work-2026-11-14/05_title_3상태_미분리.png` 로 옮겼다. 상태별로 잘라서 다시 넣어야 한다.

## v1.0 — 마우스는 항상, 설정 키는 키보드용 (2026-11-14)

### 바뀜

- **창과 버튼은 키보드 조작을 켜지 않아도 언제나 마우스로 쓸 수 있다.** 상태창, 메뉴, 토글, 드래곤 끌기 모두. 우리가 그린 것 위에서만 받고 나머지는 그대로 통과시키는 규칙은 그대로다.

- **"아래쪽에만" 을 켜면 날아서 내려간다.** 전에는 순간이동했다. 내려가는 동안에는 경계가 아직 화면 전체이고, 닿은 뒤에 띠로 바뀐다.
- **대쉬(스페이스바)에 나는 모션을 쓴다.** 시트가 없는 종은 move → idle 로 대체된다.

### 지운 것

- v0.8의 "입력이 꺼져 있어도 받는 영역"(`UiButton::always`, `FrameRegions::always`, `AlwaysGuard`) 기구. 이제 전부 항상 받으므로 필요 없다. 남겨 두면 코드 지도가 없는 기능을 가리키게 된다.

- **조용할 때 다시 그리는 횟수를 줄인다.** 전투·효과·입력·끌기가 없으면 약 10fps로 떨어진다

## v0.5 — 바탕화면 디펜스 전투 (2026-11-13)

### 바뀜

- **바탕화면 사냥이 디펜스 방식이 되었다.**
  - 전투는 화면 맨 아래 띠(작업 표시줄 바로 위)에서만 일어난다.
  - 적이 화면 왼쪽 밖에서 줄지어 걸어 들어온다. 목표는 드래곤이다.

- **캐릭터 상태창에 전투 토글 스위치와 모드 버튼(직접·스킬·자동)이 생겼다.**
  모드는 무리와 무리 사이에만 바꿀 수 있고, 바꿀 수 없을 때는 버튼이 꺼져 보인다.
- **자동 전투 경험치 상한을 껐다.** 자동으로도 제한 없이 성장한다.
  `cfg::kAutoExpCapEnabled = false`이며, 수치와 저장 필드는 그대로라 다시 켤 수 있다.
  바꾸면서 잃는 것은 [기획서](game-design.md)에 적었다.
  상한이 꺼져 있으면 상태창의 자동 경험치 막대도 숨긴다.

### 저장 파일

- 형식은 그대로다. `autoExp` 기록은 계속 쌓이지만 지금은 제한에 쓰이지 않는다.

## v0.3 — 바탕화면 자동 행동 (2026-11-13)

### 추가

- 사냥하지 않을 때 드래곤이 **쉬기 / 걷기 / 날기**를 스스로 골라 행동한다.
  고르는 확률과 이어 가는 시간, 이동 속도는 `include/core/Config.h`의 `cfg::kIdle...`에서 바꾼다.
  걷기는 화면 아래쪽을 따라 다니고, 날기는 더 빠르게 화면 위쪽까지 올라간다.
- 애니메이션 상태에 **`fly`**가 생겼다. `assets/dragons/<키>/fly.png`를 넣으면 날 때 그 시트를 쓴다.
  없으면 `move.png`, 그것도 없으면 `idle.png`로 그린다.
- 날고 있을 때는 그림자를 작고 옅게 그려 공중에 떠 있는 것을 알린다.
- **걷기는 수평으로만 움직인다.** 날다가 걷기로 넘어갈 때는 먼저 지면으로 내려온다
  (내려오는 동안에도 나는 모습이다). 공중에서 걷는 모습이 나오지 않는다.
- `dragon.txt`의 `[anim.*]`에 **`render_scale`**을 적으면 그 상태만 크게/작게 그린다.
  원본 그림이 상태마다 다른 크기로 그려졌을 때 쓴다. 바닥 기준선은 유지된다.
- 망령룡에 비행 시트(8프레임)를 넣었다.

### 고침

- **`tools/make_sheet.py`가 상태마다 다른 배율을 쓰던 문제.** 각 상태의 윤곽 높이를 저마다 칸의 70%에
  맞추는 바람에, 날개를 펼쳐 윤곽이 긴 비행이 대기의 73% 크기로 작아졌다. `--set`으로 여러 상태를
  한 번에 변환하면 기준 상태로 배율을 한 번 정해 모두에 같은 배율을 쓴다. 망령룡 시트를 다시 변환했다.
- **망령룡의 상태별 몸 크기.** 위 변환을 고친 뒤에도 원본 그림 자체가 비행에서 작게 그려져 있었다
  (흉곽 발광부 높이: 대기 145px, 걷기 128px, 비행 106px). 시트에서 키우면 날개가 잘리므로
  `render_scale`로 그리는 단계에서 맞췄다(걷기 1.13, 비행 1.37).
- `tests/balance_sim.cpp`에서 `printf("%s")`에 `std::string`을 넘기던 문제를 고쳤다.
  v0.2에서 종 이름의 타입이 바뀌며 생긴 것으로, 시뮬레이션 출력이 깨져 보였다.

### 바뀌지 않은 것

- 전투 중에는 자동 행동을 쓰지 않는다. 적이 나타나면 날기를 멈춘다.
- 저장 파일 형식은 그대로다. 자동 행동은 저장하지 않는다(게임을 켤 때마다 새로 고른다).
