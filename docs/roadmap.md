# 개발 로드맵

일정은 예측이 아니라 순서다. 각 단계는 직접 확인하고 필요한 경우 이전 설계로 돌아간다.

## 진행 상황 (2026-11-13)

**0~6단계는 모두 구현을 마쳤다.** 이후 작업은 버전 단위로 이어진다 — 현재 **v0.7**까지 `main`에 병합.
버전별 내용은 [변경 기록](changelog.md), 단계별 세부 진행과 바뀐 결정은 [구현 메모](implementation-notes.md)의 "로드맵 진행"에 있다.

단계의 "체크" 항목 중 이후 결정으로 바뀐 것:

- 4단계의 "경험치 상한을 넘지 않고 자동 중단" → v0.5에서 상한을 껐다. 되돌릴 수 있게 계산은 남겨 뒀다.
- 0단계의 "클릭 통과 세부 동작 결정" → v0.6에서 영역 기반으로 확정.

**아직 Windows에서 실제로 확인하지 않은 항목이 있다.** 이 환경에서는 `src/win`을 실행할 수 없어 CI 빌드와 코어 테스트까지만 검증된다. 확인 목록은 [구현 메모](implementation-notes.md)의 "Windows에서 확인할 것"에 모아 뒀다.

## 0. 방향 확정
- Windows용 C++ 컴파일러와 CMake를 준비한다. 그래픽·입력 라이브러리는 후보를 비교한 뒤 결정한다.
- 체크: 시작 프로젝트 빌드·실행 및 종료. 투명 창의 항상 위 표시, 설정 버튼을 통한 입력 전환, 다른 앱 전체화면 시 숨김과 복귀를 작은 실험으로 검증한다. 클릭 통과와 다중 모니터는 세부 동작을 정해 시험하고 저장 위치도 결정한다.

## 1. 수동 전투 실험
- 한 드래곤과 한 적으로 이동, 공격 예고, 회피, 피해를 시험한다.
- 체크: 공격을 보고 피할 수 있고 체력이 0이면 전투가 종료된다.

## 2. 성장과 영구 사망
- 경험치·레벨·개체 생성과 사망 상태를 추가한다.
- 체크: 재실행 후 죽은 개체는 사용할 수 없고 새 개체로 시작한다.

## 3. 스킬 수동 전투
- 자동 이동과 확률 회피, 수동 스킬을 추가한다.
- 체크: 공격마다 확률 판정이 적용되고 스킬 입력이 동작한다.

## 4. 바탕화면 자동 사냥
- 자동 행동, 진행 표시, 중단 및 개체별 경험치 상한을 만든다.
- 체크: 전체화면으로 숨겨진 동안에도 자동 사냥이 진행된다. 경험치 상한을 넘지 않고 자동 중단하며 재실행해도 누적량이 보존된다. 숨겨진 상태의 사망과 종료 시 규칙을 확인한다.

## 5. 탑 수직 단면
- 3층과 보스, 진입·결과·재도전을 연결한다.
- 체크: 탑에서 자동 사냥을 선택할 수 없고 시작부터 승리 또는 사망까지 이어진다.

## 6. 확장과 검증
- 나머지 드래곤 3종과 적·스킬을 순차 추가하고 접근성, 저장 안정성, 난이도를 검증한다.
- 체크: 각 종류의 차이가 체감되고 사망 원인과 재도전 시간이 납득 가능하다.

## 첫 작업을 위한 질문
- 입력 → 이동 → 충돌 → 피해 중 어떤 순서로 나누면 각 기능을 눈으로 확인할 수 있을까?
- 회피 성공 여부를 숫자 없이도 알아볼 수 있는 피드백은 무엇일까?
- 한 번에 기능을 늘리기보다 어떤 최소 장면으로 재미를 확인할 수 있을까?
