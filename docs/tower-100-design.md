# 탑 100층 확장 설계안

상태: 설계 · 2026-11-15. 사용자가 답한 것만 **확정**이고 나머지는 **제안** 또는 **미결정**이다.
확정 사항의 요약은 [기획서 10장](game-design.md#확정-탑-100층-확장-방향-2026-11-15)에 한 번만 적고, 이 문서에는 설계를 적는다.

## 1. 사용자가 확정한 것 (2026-11-15)

| 항목 | 결정 |
|---|---|
| 탑 층수 | 100층. 10의 배수는 **필드 보스**, 그 외 5의 배수는 **중간 보스** |
| 자동사냥 기준 층 | 드래곤이 머무는 층의 **직전 일반 층**. 보스층이면 더 아래의 가장 가까운 일반 층. 1층이면 1층 몬스터 |
| 바탕화면 사냥 | **디펜스 유지**(2026-11-16 정정: 앞서 적은 "클릭 사냥으로 교체"는 취소). 몬스터는 드래곤을 쓰러뜨리러 오고 드래곤은 몬스터를 처치한다 |
| 드래곤 보유 | 여러 마리. **사망은 개체별 영구**(기존 규칙 유지) |
| 드래곤 획득 | 전투 보상 **크레딧**으로 상점에서 **드래곤 알 구매**(가장 비싼 품목). 알의 종은 무작위. 첫 드래곤은 지금처럼 고른다 |
| 슬롯 | 기본 4칸, **20층마다 +1칸** |
| 필드 보스 | 드래곤 4마리 파티. **출전 4마리 각각** `층 × 5` 레벨 이하(포함). 4마리가 안 되면 입장 불가. 조작은 **1마리만, 나머지 3마리는 자동**(2026-11-16) |
| 탑 진행 | **드래곤마다 따로**, 새 드래곤은 1층부터. **계정이 한 번 깬 필드 보스층은 새 드래곤이 건너뛴다**(9층 → 11층). 계정이 아직 못 깬 필드 보스층에서는 그 층에서 멈추고 파티로 깬다 |
| 최고 레벨 | 500 |
| 원소 | **이번 설계에서 뺐다**(2026-11-16). 앞서 정한 드래곤 5원소·몬스터 원소는 지우고 사용자가 새로 설계한다 |
| 재화 | 이름은 **크레딧**. 획득 기준·상점 품목·가격은 4.4의 임시값(Claude가 정함, 2026-11-16). **UI 스킨은 팔지 않는다**(2026-11-16) |
| 지역·보스 | 10층마다 지역 하나, 중간보스 10종·필드보스 10종(2026-11-16). 목록·패턴·그림 규격은 [보스 구성안](tower-100-bosses.md) |

## 2. 지금 코드와의 관계

| 지금 있는 것 | 이번 확장과의 관계 |
|---|---|
| `assets/tower/floors.txt` (`[floor.N]`, 10층, 3층마다 보스) | 형식은 그대로 쓰고 **100층·5/10 보스 구조로 다시 쓴다**(T4). 지금의 10층 곡선(자동 큐 3번)은 그때 바뀐다 |
| 여러 드래곤 보유 `stable.*` (v1.3, `kMaxStable = 4`, 보관 중 체력만 회복, 전투·탑 밖에서만 교체) | 이 구조를 **그대로 확장**한다. 4는 "기본 4칸"과 같다. 슬롯 증가·알 구매를 더한다(T6) |
| 바탕화면 디펜스(`spawnWave`, 왼쪽 밖 등장) | **그대로 쓴다.** 나오는 몬스터만 사냥 기준 층(`huntFloorFor`) 구성으로 바꾼다(T3). 싸우는 자리는 "아래쪽에만" 설정을 따른다(#47) |
| 일반 적의 예고·쿨다운 | `enemy.txt` 의 `windup`·`attack_cooldown` 을 읽지만 실제로는 공통값(`cfg::kImpWindup` 등)을 쓴다(`World::enemyAttack`). 바로잡으면 지금 맞춰 둔 탑 곡선이 바뀌므로 **측정과 함께 스위치로**(T8) |
| 최고 레벨 30, 층 50개·적 레벨 99 상한 | T1에서 500 / 100층 / 500으로 올렸다 |

## 4. 설계

엔진·실행 파일을 새로 만들지 않는다. core는 win을 모른다는 원칙을 그대로 따른다.

### 4.1 층 규칙 (`core/Tower.h`) — T1에서 넣음

`floors.txt` 와 별개인 **구조 규칙**이라 순수 함수로 둔다.

```cpp
enum class FloorType { Normal, MidBoss, FieldBoss, Invalid };
FloorType floorType(int floor);          // 1~100. 10의 배수 FieldBoss, 그 외 5의 배수 MidBoss
int huntFloorFor(int currentFloor);      // 23→22, 21→19, 16→14, 11→9, 1→1. 100 정복 후(101)→99
int fieldBossLevelCap(int floor);        // 필드 보스층이면 floor*5, 아니면 0
bool partyMeetsLevelCap(int floor, const std::vector<int>& levels); // 4마리 각각 상한 이하
```

수치는 `Config.h` 의 `kTowerTopFloor`, `kMidBossEvery`, `kFieldBossEvery`, `kFieldBossLevelPerFloor`, `kFieldBossPartySize`.

### 4.2 층 데이터 (`floors.txt` 확장) — T4

지금 형식(`[floor.N]`, `enemy=키 xN lvN`)을 그대로 쓰고 두 가지만 더한다.

- `element=` — 층(또는 구간)의 원소. 필드 보스의 원소가 된다.
- 반복을 줄이는 **구간 구역** `[floors.11-19]` — 적힌 값을 그 범위의 일반층 기본값으로 쓰고, `[floor.N]` 이 있으면 그 층이 이긴다.

지역별 몬스터와 보스 20종은 [보스 구성안](tower-100-bosses.md)으로 확정했다(2026-11-16). 수량·능력치는 미결정이다. **처음에는 지금 있는 적(슬라임·고블린·오우거·리치와 정예 3종)만으로 100층을 채워** 흐름을 확인하고, Codex의 새 몬스터가 들어오면 표만 바꾼다.

### 4.3 원소 — 보류

이번 설계에서 뺐다(2026-11-16). 사용자가 새로 설계하면 이 절을 다시 쓴다. 그때까지 원소 계산·저장 키·표 파일은 만들지 않는다.

### 4.4 보유·크레딧·상점 — T2(저장 키, 2026-11-18 넣음)·T6

`stable.*` 저장 키에 **필드만 더한다.** 모르는 키는 옛 빌드가 무시하므로 호환이 깨지지 않는다.

| 키 | 내용 |
|---|---|
| `dragon.floor` / `stable.N.floor` | 그 드래곤이 머무는 탑 층(없으면 1) |
| `dragon.cleared` / `stable.N.cleared` | 그 드래곤이 돌파한 가장 높은 층(재돌파 보상 판정) |
| `credits` | 크레딧(계정 공용, 64비트 정수) |
| `tower.fieldBossCleared` | 계정이 깬 필드 보스층(예: `10,20`) |
| `tower.firstClear` | 계정이 처음 돌파한 가장 높은 층(첫 돌파 보상 판정) |

슬롯 수 = `kMaxStable(4) + 깬 필드 보스 중 20의 배수 개수`.

#### 크레딧 기준 — Claude가 정한 임시값(`Config.h` 상수로 뺀다)

**가장 약한 몬스터 한 마리 = 2 크레딧.** 모든 값을 이 단위로 생각한다.

| 얻는 곳 | 양 | 이유 |
|---|---|---|
| 바탕화면 사냥 처치 | `2 + 적 레벨 ÷ 5`(버림). Lv1~4 2 · Lv5~9 3 · Lv10 4 … Lv500 102 | 초반이 너무 느리지 않게(2026-11-16 조정: 처음 안 `1 + 레벨 ÷ 10` 의 약 2배) |
| 정예 처치 | 위 × 3 | 드물고 세다 |
| 자동 사냥 | 위 × 0.7(버림, 최소 1) | 손이 덜 가는 만큼 덜 준다. 직접 조작·스킬 수동을 고를 이유를 남긴다 |
| 탑 일반층 첫 돌파 | `층 × 10` | 등반이 주 수입원이 되게 |
| 중간 보스 첫 처치 | `층 × 30` | 5층 150 · 95층 2,850 |
| 필드 보스 첫 처치(파티) | `층 × 100` | 10층 1,000 · 50층 5,000 · 100층 10,000 |
| 계정이 이미 깬 층을 다른 드래곤이 돌파 | 첫 돌파의 20% | 진행이 드래곤마다 따로라, 새 드래곤으로 큰 보상을 반복해 뽑지 못하게 |
| 탑을 나가거나 드래곤이 죽음 | 잃지 않는다 | 크레딧은 계정 것. 영구 사망의 손실은 드래곤과 레벨이다 |

대략적인 흐름(추정 — T6에서 `balance_sim` 으로 잰다): 초반 사냥은 분당 3~6마리라 **시간당 약 400~700**, 1~9층 첫 돌파 합계 약 550. 2번째 알은 초반 기준 약 4~6시간, 4마리 파티까지는 하루 이틀.

#### 상점 — 임시 품목과 가격

영구 사망을 없애는 물건(부활, 사망 무효)은 **팔지 않는다.** 탑 안 회복은 아래 탑 물약만, 제한을 걸어 판다.

| 품목 | 가격 | 효과 | 제한 |
|---|---|---|---|
| **드래곤 알** | `3,000 + 1,000 × (살아 있는 드래곤 수 − 1)` → 2번째 3,000 · 3번째 4,000 · 4번째 5,000 | 즉시 부화, 종 무작위, Lv1 | 빈 슬롯이 있어야 한다 |
| 탑 물약(소) | 50 | 체력 30% 회복 | **탑 안에서만**. 아래 제한 |
| 탑 물약(대) | 150 | 체력 60% 회복 | **탑 안에서만**. 아래 제한 |
| 훈련서 | `현재 레벨 × 20` | 다음 레벨까지 필요한 경험치의 25% | 레벨이 오를수록 비싸진다 |

**탑 물약 제한**(2026-11-16 사용자 결정 — 바탕화면은 무료 회복이 충분해 물약을 탑 전용으로 바꿨다)

- 한 번 오를 때 **최대 2개**까지 가지고 들어간다. 탑 진입 경고창(`Screen::TowerWarning`)에서 고르고, 쓰지 않은 것은 나올 때 돌려받는다.
- **마시는 데 1초**. 그동안 이동이 느려진다(보스 공격 직전에 마셔 넘기는 것을 막는다).
- **부활은 안 된다.** 체력이 0이 되면 지금처럼 영구 사망이다. 바탕화면에서는 쓸 수 없다.
- 지금 탑 난이도는 물약 없이 잰 값이다. T4에서 100층을 다시 맞출 때 **물약 2개를 쓰는 것을 전제로** 맞춘다.

알 가격 근거: 2번째 알이 초반 기준 **약 4~6시간**, 10층 파티(4마리)까지 알 3개 12,000은 첫 돌파 보너스를 합쳐 **하루 이틀**이 걸리게 했다("많이 비싸게"). 실제로 재 본 뒤 조정할 수 있는 값이다.

### 4.5 성장: 최고 레벨 500 — T1에서 상한만 올림

지금 식으로 1→500 누적은 약 4.2억, 499→500 한 칸은 약 250만이다. 32비트 정수(약 21억) 안이라 **이번에는 형을 바꾸지 않고 테스트로 범위를 감시**한다. 보상 배율이 커지거나 곡선을 바꾸면 그때 64비트로 옮긴다.
스킬 칸 상한(`kMaxSkillsPerDragon`)은 지금까지 최고 레벨과 같은 값(30)이었다. 레벨을 올려도 스킬 칸이 500으로 늘지 않게 **30으로 따로 고정**했다.

### 4.6 바탕화면 사냥 — T3(2026-11-18 넣음)

- **지금의 디펜스를 유지한다.** 적은 왼쪽 밖에서 들어와 드래곤을 노리고, 드래곤은 적을 처치한다.
- 싸우는 자리는 "아래쪽에만" 설정을 따른다 — 켜면 맨 아래 띠, 끄면 화면 전체(#47, 이미 반영).
- T3에서 바꾸는 것은 **나오는 몬스터**뿐이다: 지금의 `randomMelee`(등록된 일반 적 무작위) 대신 `huntFloorFor(드래곤 층)` 층의 몬스터 구성으로 무리를 만든다.

### 4.7 파티 — T7

조작: **1마리만 플레이어가 조작**(현재 모드), 나머지 3마리는 자동 사냥과 같은 AI로 싸운다(확정 2026-11-16).

검사: 4마리 → 중복 없음 → 모두 생존 → 모두 레벨 상한 이하 → 모두 그 층에 도달(제안).
`World` 가 드래곤 1마리 기준이라 `DragonActor` 를 배열로 바꾸는 것이 가장 큰 작업이다. 그래서 마지막에 둔다.
여러 마리가 동시에 쓰러지면 **한 번의 저장에 모두 반영**한다(사망 즉시 저장 규칙 유지).

### 4.8 몬스터 행동 — T8

`enemy.txt` 에 공격 모양을 더한다. 예고는 항상 판정보다 먼저 보인다(핵심 규칙).

```
element=dark
[attack]
kind=swing          ; swing 부채꼴 / lunge 돌진 후 물기 / slam 원형 / shot 투사체
windup=0.8
range=72
arc=100             ; swing
lunge_distance=160  ; lunge
cooldown=2.2
[anim.attack]
hit_frame=5         ; 이 칸에서 판정(예고 끝과 맞춘다)
```

오크 = `swing`(몽둥이), 울프 = `lunge`(달려들어 물기). 나머지는 몬스터마다 사용자와 정한다.

## 5. Codex에 전달할 몬스터 이미지 규격

- 폴더 `assets/enemies/<키>/`, 키는 영문 소문자이며 **한 번 정하면 바꾸지 않는다**(도감에 기록됨).
  일반 몬스터 20종은 받았다(2026-11-16). 지역 배치와 보스 그림 규격은 [보스 구성안](tower-100-bosses.md)을 따른다.
- 시트: 투명 PNG, 오른쪽 지향, 가로 한 줄, 칸 256×256, 발 (128, 240). `idle`·`move`·`attack`·`hit`·`death`. 없으면 `idle` 로 대체, 그림이 없으면 도형.
- 프레임 수 자유, 속도·반복은 `[anim.<상태>] fps`·`loop`, 크기는 `render_scale`(판정은 `radius`).
- 공격 시트마다 **닿는 칸 번호**를 알려 준다(`hit_frame`).
- 원거리 투사체·효과는 몸과 분리한 `projectile.png`.
- 보스는 칸 512px로 받는다([보스 구성안](tower-100-bosses.md)). 엔진이 512 칸을 그대로 읽는지는 첫 보스(5층 고블린 족장)로 검증한다.
- 그림을 빌려 쓸 때는 지금 있는 `art_from=` 을 쓴다.
- `CREDITS.md` 에 제작자·도구·날짜·출처·라이선스.

## 단독 100층과 탑 선택창

2026-11-20 결정에 따라 UI와 단독 탑을 먼저 연결한다. 5의 배수는 중간 보스, 10의 배수는 필드 보스다. 두 유형 모두 현재 드래곤으로 즉시 도전하며 자동 사냥은 계속 금지한다. T4의 100층 구성은 기존 적 에셋을 재사용한 임시값이며 원소·파티·상점·전용 보스 보상은 후속 단계다. 권장 레벨은 층 데이터의 최고 적 레벨이며 초기 구성에서 층 × 5다.

층 선택은 최고 돌파 +1, 최대 100층에서 시작한다. 개체의 실제 돌파 층과 계정 첫 돌파 층은 별개 집합에 저장한다. 배열에서 건너뛴 층은 미격파로 남긴다. 옛 순차 저장은 당시 기본 탑의 범위인 1~10층 내에서 확인할 수 있는 최고 기록까지 이관한다. 옛 저장과 단독 보스 기록은 파티용 필드 보스 보상이나 슬롯을 열지 않는다. 마지막 층 첫 돌파 경험치 보너스는 계정당 한 번만 적용하며 일반 적 처치 경험치는 기존대로 지급한다.
