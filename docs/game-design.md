# 통합 게임 기획서

상태: 초안 · 2026-11-11. 사용자가 정한 방향과 검증 전 가정을 구분한다. 드래곤 종류와 수치 등은 명시된 경우 임시안이다.

## 1. 콘셉트

플레이어는 네 종류 중 드래곤 하나를 선택해 성장시키고, 사냥으로 준비한 뒤 탑에 도전한다. 드래곤이 죽으면 그 개체는 영구적으로 사용할 수 없고 새로운 드래곤으로 다시 시작한다. 탑 정복이 최종 목표다. 싱글 플레이를 가정하며 적의 정체와 세계관은 미정이다.

## 2. 핵심 루프

드래곤 선택 → 바탕화면 사냥으로 경험치 획득 → 성장과 스킬 준비 → 탑 진입 및 층별 전투 → 보상 또는 사망 → 새 드래곤 선택과 재도전. 사냥 중에도 전투를 관찰하고 모드를 선택한다. 탑은 명시적으로 진입하고 바탕화면 자동 사냥은 탑에서 사용할 수 없다.

## 3. 드래곤과 성장

초기 후보는 화염(공격), 대지(방어), 바람(기동), 물(회복/지속)이다. 이름과 특성은 확정이 아니라 서로 다른 플레이 감각을 검증하기 위한 예시다. MVP에서는 한 종류만 먼저 시험한다. 개체는 레벨과 경험치, 능력치, 장착 스킬, 생존 상태를 가진다. 레벨이 오르면 기본 능력치가 상승하고 특정 레벨에 스킬을 배운다. 구체 수치는 플레이 테스트 후 결정한다.

## 4. 전투 모드

| 모드 | 플레이어 | 드래곤 | 사용 장소 |
|---|---|---|---|
| 직접 조작 | 이동·회피·스킬 사용 | 입력에 따라 행동 | 바탕화면 사냥과 탑 |
| 스킬 수동 | 스킬 사용 | 자동 이동, 공격 회피는 확률 판정 | 바탕화면 사냥과 탑 |
| 자동 사냥 | 사냥 시작·중단 | 이동·공격·스킬을 자동 처리 | 바탕화면 사냥만 |

적 공격은 예고 후 판정해 직접 조작에서 보고 피할 수 있게 한다. 스킬 수동 모드의 회피 확률은 공격마다 판정하며, 무적을 보장하지 않는다. 모드별 공통 체력·피해·스킬 규칙을 사용한다. 모드 전환은 전투가 끝난 뒤 허용하는 것을 가정한다. 사냥은 실제 Windows 바탕화면 위에서 진행한다. 표시와 입력의 정해진 방향은 아래와 같다.

### 바탕화면 표시와 입력: 확정된 방향

- 드래곤과 몬스터는 일반 프로그램 창보다 항상 위에 표시한다.
- 다른 앱이 전체화면이 되면 드래곤, 몬스터와 설정 버튼을 숨긴다. 전체화면이 끝나면 다시 표시한다.
- 전체화면 중에도 이미 진행 중인 자동 사냥은 계속된다. 숨김은 일시정지가 아니다.
- 바탕화면에 설정 버튼을 띄우고, 사용자가 이 버튼으로 게임의 마우스·키보드 입력을 활성화하거나 끈다.
- 일반 창과 전체화면 전환, 입력 전환은 Windows 환경에서 실제 동작을 검증한다. 전체화면의 형태와 다중 모니터에 따른 감지 방식은 구현 전 검토한다.

아직 결정하지 않은 세부 사항: 게임 조작이 꺼졌을 때 캐릭터와 빈 공간의 클릭 처리, 직접 조작 또는 스킬 수동 상태에서 전체화면으로 전환한 뒤의 동작, 버튼의 세부 위치와 복귀 조작.
## 5. 자동 사냥 제한과 위험

> **이 장의 경험치 상한은 현재 꺼져 있다.** v0.5에서 바꿨다 — [바뀐 확정 사항: 자동 사냥 경험치 상한](#바뀐-확정-사항-자동-사냥-경험치-상한-2026-11-13)을 먼저 볼 것. 아래 본문은 상한을 다시 켤 때의 기준으로 남겨 둔다. 사망 위험과 경고 규칙은 그대로 유효하다.

초기 실험안: 개체별 자동 사냥 누적 경험치를 **해당 개체의 레벨 5 도달에 필요한 총 경험치**로 제한한다. 상한에 도달하면 자동 사냥은 즉시 중단하고 알림을 표시한다. 직접 조작과 스킬 수동 사냥은 이 자동 획득량에 포함하지 않는다. 진행률과 남은 자동 경험치를 표시하고 저장한다. 사망 후 새 개체는 새 상한을 가진다. 수치는 임시값이며 레벨업 중 초과 경험치도 정확히 잘라 상한을 넘기지 않는다.

자동 사냥은 다른 앱의 전체화면으로 게임이 숨겨진 동안에도 진행된다. 경험치 상한과 사망 규칙은 동일하게 적용한다. 자동 사냥도 피해와 영구 사망 위험이 있다. 위험을 숨기지 않도록 시작 전에 경고하고, 체력과 중단 버튼을 표시한다. 최초 MVP에서는 게임이 실행 중일 때만 진행하며 종료·일시정지·충돌 후 오프라인 보상은 없다. 자동 사냥에서 죽으면 동일한 영구 사망 규칙을 적용한다. 방치로 인한 손실이 납득 가능한지는 테스트 후 조정한다.

## 6. 탑과 난이도

프로토타입은 일반 적 1종, 보스 1종, 3층으로 구성한다. 층마다 공격 예고와 행동 패턴을 익히게 하고 마지막 층에서 조합한다. 보상은 층 진행과 성취를 중심으로 시험한다. 수동 모드는 숙련에 따른 회피, 스킬 수동은 스킬 선택과 확률 관리가 차이를 만든다. 모드 간 성능 차이는 의도적으로 관찰하되 수치상 우열은 아직 정하지 않는다.

난이도 조정 시 평균 승률뿐 아니라 초견 사망 원인, 회피 가능성, 한 판 길이, 재도전까지 걸리는 시간을 기록한다. 공격 신호가 보이지 않거나 이해할 수 없는 죽음은 수치 조정보다 먼저 수정한다.

## 7. 저장과 예외

개체 ID, 생존 상태, 레벨·경험치, 자동 경험치 누적, 최고 층과 도감을 저장한다. 사망을 확정할 때 생존 상태를 저장해 재실행으로 부활하지 않게 한다. 저장 손상이나 강제 종료의 복구 정책은 별도 설계·검증한다. MVP는 로컬 저장을 가정하며 서버 및 부정행위 방지는 범위 밖이다.

## 8. 성공 기준과 범위

첫 수직 단면의 목표는 드래곤 선택부터 사냥·성장·탑 진입·사망·새 개체 선택까지 한 번 이어서 플레이할 수 있는 것이다. 네 종류 전체, 풍부한 적, 밸런스 완성, 온라인 기능, 상용 배포는 첫 수직 단면의 필수 범위가 아니다. 개발 단계는 [로드맵](roadmap.md)을 따른다.

## 9. 기술 방향

게임에는 배경 음악과 효과음 등 소리를 넣지 않는다. 게임 상태와 위험은 시각적 수단으로 전달한다.

Windows PC를 대상으로 C++을 사용하며 게임 엔진은 사용하지 않는다. CMake를 빌드 구성에 사용한다. 그래픽·입력 라이브러리는 미정이고, 필요 시 Windows API를 사용한다. 투명 창과 입력 동작은 구현 가능성을 먼저 시험한다.

## 10. 확정 사항과 남은 미결정 사항

### 확정: 바탕화면 표시와 입력

- 일반 프로그램 창 위에 드래곤과 몬스터를 표시한다.
- 다른 앱이 전체화면이면 드래곤, 몬스터, 설정 버튼을 숨기고 전체화면 종료 후 다시 표시한다.
- 전체화면 중에도 자동 사냥은 계속한다.
- 화면의 설정 버튼으로 게임 마우스·키보드 입력을 켜고 끈다.

### 확정 변경: 바탕화면 디펜스 전투 (2026-11-13, v0.5)

바탕화면 사냥을 **디펜스 방식으로 바꾼다.** 화면 전체를 돌며 무작위 가장자리에서 적이 나오던 방식은 없앤다.

- 전투는 **화면 맨 아래 띠**(작업 표시줄 바로 위)에서만 일어난다. 띠 높이는 `cfg::kBandHeight`.
- 적은 **화면 왼쪽 밖에서** 줄지어 걸어 들어와 드래곤에게 온다. 목표는 드래곤이다.
- 적의 레벨은 드래곤 레벨에 맞춘다. 웨이브가 쌓일수록 한 번에 나오는 수가 는다(`cfg::kWaveMax`까지).
- 전투를 켜고 끄는 것은 **캐릭터 상태창의 토글 스위치**로 한다. 모드(직접·스킬 수동·자동)도 상태창에서 고른다.
- 전투를 끄면 드래곤은 다시 바탕화면 전체를 돌아다닌다(v0.3의 쉬기·걷기·날기).

**바뀜 (2026-11-16, #47): 싸우는 자리는 "아래쪽에만" 설정을 따른다.** 켜면 위처럼 맨 아래 띠에서, 끄면 **화면 전체**에서 싸운다. 적은 그대로 왼쪽 밖에서 들어오되 드래곤이 있는 높이 근처로 온다. 사냥 중에 설정을 바꾸면 바로 적용된다(켜면 띠로 날아 내려간다).

**[5장 자동 사냥 상한](#5-자동-사냥-제한과-위험)을 바꾼다: 자동 전투 경험치 상한을 끈다.**
자동으로도 레벨 제한 없이 성장한다. 아래 "바뀐 확정 사항"에 적었다.

### 바뀐 확정 사항: 자동 사냥 경험치 상한 (2026-11-13)

**상한을 끄기로 했다.** 코드에서는 `cfg::kAutoExpCapEnabled = false`이며, 수치와 저장 필드(`autoExp`)는
그대로 두어 언제든 다시 켤 수 있다.

바꾸면서 잃는 것을 적어 둔다(되돌릴지 판단할 근거다).

- 상한은 "자동으로는 레벨 5까지만, 그 위는 직접 조작으로"라는 **성장 경로의 분기**를 만들던 장치였다.
  끄면 자동만 켜 두어도 최고 레벨까지 갈 수 있어, 직접 조작·스킬 수동을 고를 이유가 약해진다.
- 영구 사망의 무게도 줄어든다. 위험을 감수하지 않고 시간만 들이면 성장할 수 있기 때문이다.
- 다만 자동 전투에도 **사망 위험은 그대로** 있다(숨겨진 동안에도 진행된다).

되돌리려면 `kAutoExpCapEnabled`를 `true`로 바꾸면 된다. 관련 계산은 테스트가 계속 검증하고 있다
(`testAutoCapClamp`가 `setAutoExpCapOverride`로 켠 상태를 확인한다).

### 다음 버전 요청: 게임 중 캐릭터 교체 (2026-11-13 메모)

현재는 **살아 있는 드래곤이 없을 때만** 선택 화면이 열린다(첫 실행 또는 사망 직후). 게임 도중에는
드래곤을 바꿀 수 없다. 다음 배포에서 바꿀 수 있게 해 달라는 요청이 있었다.

요청이 두 가지로 읽히고, 게임에 미치는 영향이 완전히 다르다. **만들기 전에 어느 쪽인지 정해야 한다.**

**가. 개발·확인용 전환** — 새로 만든 드래곤 그림을 바로 보려는 용도.
- 지금은 보려면 저장 파일을 지우거나 드래곤이 죽기를 기다려야 한다. 불편하다.
- 게임 규칙은 건드리지 않는다. 설정 버튼이나 단축키로 **보기 전용 미리보기**를 열고,
  그 안에서 종·상태(대기/이동/공격)·크기를 돌려 본다. 개체의 레벨·경험치·생존 상태는 바뀌지 않는다.
- 기존 규칙과 충돌하지 않으므로 바로 만들 수 있다.

**나. 여러 드래곤을 키우며 바꿔 쓰기** — 게임 기능으로서의 교체.
- **[3장 영구 사망](#3-드래곤과-성장)·[5장 자동 사냥 상한](#5-자동-사냥-제한과-위험)과 정면으로 부딪친다.**
  정하지 않으면 규칙이 무너진다.
  - 영구 사망의 무게가 줄어든다. 죽어도 다른 드래곤이 있으면 "다시 시작"이 아니라 "한 마리 손실"이 된다.
  - 자동 경험치 상한이 **개체별**이라, 여러 마리를 번갈아 돌리면 상한을 사실상 우회할 수 있다.
  - 탑에서 불리할 때 바꿔 끼우면 위험 부담이 사라진다.
- 만들려면 최소한 이것들을 정해야 한다: 동시에 가질 수 있는 마리 수, 새 드래곤을 얻는 조건,
  교체 가능한 시점(전투 중 불가·무리 사이만·탑 안 금지 등), 자동 경험치 상한을 개체별로 둘지
  계정 전체로 둘지, 교체한 드래곤이 쉬는 동안 회복하는지, 저장 형식 변경과 기존 저장 호환.

제안: **가를 먼저 넣고, 나는 따로 정한 뒤에 넣는다.** 가는 규칙을 건드리지 않아 금방 되고,
나는 사실상 게임 구조를 바꾸는 일이라 위 항목을 정하지 않으면 영구 사망 규칙이 이름만 남는다.

### 확정: 스킬 해제와 장착 (2026-11-14, v1.4)

[망령룡 스킬 기획 V1](characters/revenant-dragon-skills-v1.md)이 "기본 공격 2종·패시브·액티브 4종을
현재 3슬롯에 직접 대응시킬 수 없음. 장착/확장 여부 미정"으로 남겨 둔 항목을 아래로 정하고 구현했다.

| 항목 | 정한 것 | 이유 |
|---|---|---|
| 해제 | **레벨마다 스킬 하나씩.** `level=`을 적으면 그 레벨, 적지 않으면 비어 있는 가장 낮은 레벨이 목록 순서대로 배정된다 | 레벨업마다 눈에 보이는 보상이 생긴다. 스킬을 뒤에 더하기만 해도 되어 추가가 쉽다 |
| 스킬 개수 | **제한 없음**(안전장치로 최고 레벨까지). 종마다 다르게 가질 수 있다 | 드래곤마다 개성을 다르게 줄 수 있다 |
| 장착 | **액티브는 4칸까지**(`kSkillSlots`). 조작키 1~4가 곧 칸이다 | 키 개수와 칸 수를 같게 해서 "몇 번 키가 무슨 스킬인가"를 헷갈리지 않게 한다 |
| 자동 전투 | **장착한 것만 쓴다.** 칸 순서가 우선순위 | 자동이 전부 쓰면 고를 이유가 없어지고, 자동이 수동보다 강해진다 |
| 패시브 | **칸을 쓰지 않는다.** 해제되면 항상 적용 | 고를 여지가 없는 것을 칸에 넣으면 선택이 아니라 세금이 된다 |
| 빈 칸 | 해제된 액티브가 남아 있으면 **자동으로 채워진다** | 관리창을 열지 않아도 새 스킬이 쓰인다. 쓰기 싫으면 다른 스킬로 덮어쓴다 |
| 변경 시점 | **전투·탑 밖에서만**. 탑에서는 창 자체가 열리지 않는다 | 드래곤 교체와 같은 이유. 창이 떠 있는 동안 전투가 멈추므로 시간 벌기가 된다 |
| 저장 | `dragon.slots` / `stable.<번호>.slots` 를 더했다. 없는 옛 파일은 자동으로 채운다 | 호환 유지 |

**기존 임시 스킬은 이름을 바꾸거나 교체하지 않았다**(스킬 기획 V1의 요청). 새 스킬은 뒤에 더했고
해제 레벨은 자동 배정에 맡겼다. **수치는 전부 임시값이며 플레이 테스트로 정한다.**

### 확정: 여러 드래곤 보유와 교체 (2026-11-14, v1.3)

위 "나"를 아래 규칙으로 정하고 구현했다. 영구 사망은 그대로 유지된다.

| 항목 | 정한 것 | 이유 |
|---|---|---|
| 동시 보유 | 최대 4마리(`cfg::kMaxStable`). 언제든 데려올 수 있다 | 단순하고 바로 쓸 수 있다 |
| 보관 중 | **체력만 서서히 회복**(1초에 최대 체력의 2%). 경험치는 오르지 않는다 | 한 번에 한 마리만 키우게 해서 영구 사망의 무게를 지킨다. 자동 경험치 상한 우회도 막힌다 |
| 교체 시점 | **전투·탑 밖에서만** | 불리할 때 바꿔 끼워 위험을 피하는 것을 막는다 |
| 죽은 개체 | 보유 목록에서 **빠지고 묘비로만 남는다**. 되살릴 수 없다 | 영구 사망 유지. 자리도 비워 준다 |
| 죽은 뒤 | 남은 드래곤이 있으면 **관리창이 열린다**(자동 교체하지 않는다) | 죽음이 그냥 넘어가지 않도록 한 번은 사람이 고르게 한다 |
| 저장 | `stable.*` 키를 더했다. 옛 `dragon.*` 키도 계속 써서 이전 빌드에서도 읽힌다 | 호환 유지 |

**바탕화면에 띄운 드래곤이 곧 플레이하는 드래곤이다.** 둘을 따로 두지 않는다.

### 확정: 클릭 통과 범위 (2026-11-13, v0.6)

게임 입력을 켜도 **드래곤·몬스터·패널·버튼이 그려진 자리에서만** 입력을 받는다. 그 밖은 바탕화면과
다른 창으로 통과시킨다. 선택 화면·탑·모달이 떠 있을 때만 화면 전체를 받는다.
구현은 매 프레임 그린 것들의 영역을 모아 커서 위치와 견주는 방식이다(`FrameRegions`).

**바뀜 (2026-11-14, v1.0): 마우스는 언제나 받는다.** 아래 v0.8의 보탬을 넓힌 것이다.
창과 버튼은 키보드 조작을 켜지 않아도 마우스로 쓸 수 있다. "그린 것 위에서만 받고 나머지는
통과"라는 원칙은 그대로이고, 설정 버튼은 **키보드 조작**(이동·회피·스킬)만 켜고 끈다.
키보드를 쓰려면 창이 활성화되어야 해서, 그때만 쓰던 프로그램의 포커스를 가져온다.
선택 화면·탑·모달이 화면 전체를 막는 것도 키보드 조작이 켜져 있을 때만이다.

**보탬 (2026-11-14, v0.8): 상태창은 입력이 꺼져 있어도 받는다.** 위 규칙은 그대로이고 예외가 하나
늘었다. 상태창(캐릭터 상태 카드)은 게임 입력을 켜지 않아도 옮기고 접고 전투 토글을 누를 수 있다.
게임 입력을 켜면 화면이 어두워지고 다른 창으로 가는 클릭이 제한되는데, 상태창을 만지려고 그걸
켜야 하는 것은 과했다. 상태창 위에서만 받고 나머지는 그대로 통과시키므로 "그린 것 위에서만
받는다"는 원칙은 유지된다. 구현은 `FrameRegions::always`와 `UiButton::always`다.

### 확정: 탑 100층 확장 방향 (2026-11-15)

사용자가 정했다. 설계·단계(T1~T8)·남은 미결정은 [탑 100층 확장 설계안](tower-100-design.md).

- 탑은 100층. 10의 배수는 **필드 보스**(드래곤 4마리 파티), 그 외 5의 배수는 **중간 보스**.
- 필드 보스 입장: 출전 4마리 **각각** `층 × 5` 레벨 이하(그 레벨 포함 — 10층 50 … 100층 500). 4마리가 안 되면 들어갈 수 없다.
- 최고 레벨 500.
- 탑 진행은 **드래곤마다 따로**, 새 드래곤은 1층부터. **계정이 한 번 깬 필드 보스층은 새 드래곤이 건너뛴다**(9층 → 11층). 아직 못 깬 필드 보스층에서는 멈추고 파티로 깬다.
- 바탕화면 사냥은 **지금의 디펜스 방식을 유지한다**(2026-11-16 정정 — 앞서 적었던 "클릭 사냥으로 교체"는 취소). 몬스터의 목표는 드래곤을 쓰러뜨리는 것이고 드래곤은 몬스터를 처치한다. 나오는 몬스터는 드래곤이 머무는 층의 **직전 일반 층** 몬스터다(보스층은 건너뜀, 1층이면 1층).
- 드래곤은 여러 마리(위 "여러 드래곤 보유와 교체"를 확장), **사망은 개체별 영구**. 새 드래곤은 전투 보상 재화로 산 **알**에서 무작위 종으로 태어난다. 슬롯은 기본 4칸, 20층마다 +1칸.
- **원소는 이번 설계에서 뺐다**(2026-11-16). 앞서 정한 드래곤 5원소·몬스터 원소는 지우고 사용자가 새로 설계한다.
- 재화는 **크레딧**(2026-11-16). 사냥·탑 돌파로 얻고 상점에서 쓴다. **드래곤 알이 가장 비싼 품목**이다. 회복 물약은 **탑 안에서만** 쓰고 한 번 오를 때 최대 2개(부활·사망 무효는 팔지 않는다). 획득 기준·품목·가격은 [설계안 4.4](tower-100-design.md#44-보유크레딧상점--t2t6)(임시값).
- 상점에서 **UI 스킨은 팔지 않는다**(2026-11-16).
- 탑은 10층마다 지역이 바뀌고 **중간보스 10종·필드보스 10종**을 둔다(2026-11-16). 필드보스는 입장에만 4마리가 필요하고, 한 마리가 죽어도 남은 파티로 공략할 수 있어야 한다. 목록은 [보스 구성안](tower-100-bosses.md).
- 필드 보스 파티는 **1마리만 조작하고 나머지 3마리는 자동**으로 싸운다(2026-11-16).

### 확정: 망령룡 저주 중첩 (2026-11-19)

- 적마다 전투 중 저주를 독립적으로 보유한다. 최대 5중첩, 마지막 부여부터 6초다. 상한에서도 재부여하면 시간은 갱신된다. 사망하면 소멸하며 저장하지 않는다.
- 영혼 탄은 실제 명중할 때 1중첩을 부여한다. 저주의 안개는 유효한 피해 범위에 들어온 적에게 첫 피해 틱부터 중첩을 부여할 수 있다. 이후 안개 부여에는 적별로 1초 간격이 필요하며, 겹치는 장판끼리 간격을 공유한다.
- 기본 공격과 다른 종은 적용 범위 밖이다. 저주 자체의 추가 피해는 없다. 저주 소비·폭발, 궁극기 충전과 죽음의 행렬은 별도 설계 대상이다.

### 확정: 망령룡 영혼 자원 (2026-11-19)

- 영혼 수확이 해제된 망령룡은 확정된 적 처치마다 영혼 1개를 얻으며 최대 10개를 보유한다. 회복은 기존 최대 체력 6% 규칙을 따른다.
- 영혼은 현재 드래곤의 전투 세션에 속하며 저장하지 않는다. 사냥 시작·종료, 탑 도전 시작·정복·퇴장, 드래곤 교체·사망, 재실행에서 초기화한다. 같은 탑 도전의 층 이동은 영혼을 유지한다.
- 획득 시 `영혼 +1`과 상태창 보유량을 표시한다. [망령룡 스킬 기획](characters/revenant-dragon-skills-v1.md#pr-2--영혼-수확)

### 확정: 망령룡 궁극기 충전 (2026-11-19)

- 영혼 수확이 해제된 망령룡은 현재 영혼 1개당 10%, 10개일 때 100% 충전된다. 충전은 별도로 저장하거나 누적하지 않는다.
- 상태창에서 기존 영혼 표시를 청록색 게이지와 합치고, 100%일 때 스킬 미구현을 함께 표시한다.
- 발동 조건에는 궁극기 해제, 전투 상태, 시전 허용 여부가 포함된다. 실제 공격은 후속 PR에서 구현한다.
- 시전 준비는 자원을 차감하지 않는다. 이후 지정한 타격이 확정되면 해당 시전에서 영혼 10개를 한 번만 차감한다. 타격 전 취소 및 기존 영혼 초기화 시 소비 요청은 폐기된다.
