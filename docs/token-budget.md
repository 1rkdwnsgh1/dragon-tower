조사 원본은 [archive/token-notes-2026-11-16.md](archive/token-notes-2026-11-16.md) 다.

여기에는 **확인했고 쓸 수 있는 것만** 남긴다.

## 쓰는 것

### 1. 읽을 문서를 라우팅한다 — 효과 가장 큼

2026-11-17 개편 전에는 `AGENTS.md` 가 "어떤 작업이든 시작 전에 18개 문서를 모두 확인"하라고
적어 두었다. 그 18개 합계가 **약 336KB(한글 약 11만 자)** 였다. 지금은
[STATE.md](STATE.md) + [INDEX.md](INDEX.md) 두 개만 읽고, 라우팅 표에서 그 작업에 필요한
2~3개만 읽는다.

**고정 읽기 336KB → 약 12KB.**

### 2. 명령을 묶는다 — 단 조회만

서로 상관없는 조회는 `&&` · `;` 로 이어 한 번에 실행한다. 한 회차 `Bash` 호출 10회 이하를 목표로 한다.
(2026-11-16 세션은 28회를 불렀고, 그중 7회는 묶을 수 있었다.)

**되돌릴 수 없는 동작(머지·푸시·삭제)은 묶지 않는다.** 실제로 사고가 났다 — CI 폴링 루프를
`&& gh api .../merge` 로 이었는데, 루프는 "확인이 끝났다"로 종료 코드 0을 내기 때문에
**CI 실패 상태로 PR 이 머지됐다.**

판정을 종료 코드로 끌어올려야 한다.

```bash
echo "$R" | grep -q 'failure'            && { echo "CI 실패 — 머지하지 않는다"; exit 1; }
echo "$R" | grep -qE 'in_progress|queued' && { echo "CI 미완 — 머지하지 않는다"; exit 1; }
gh api .../merge -X PUT ...
```

### 3. 도구 출력을 받기 전에 줄인다

세어 보려면 **세는 명령**을 쓰고 목록을 가져오지 않는다. 한 번 받은 100줄은 세션 끝까지 남는다.

```bash
gh api ... -q '...'                        # jq 를 CLI 단계에서 적용
... | awk -F/ '{print $1"/"$2}' | sort -u  # 목록 대신 집계
... | wc -l                                # 개수만 필요하면 개수만
cmake --build build 2>&1 | tail -5         # 빌드 로그는 끝 몇 줄만
```

### 4. 위치는 codemap 으로 찾고 grep 으로 좁힌다

`Renderer.cpp`(약 1060줄) · `World.cpp`(약 680줄)를 통째로 읽지 않는다.
[codemap.md](codemap.md) 에서 이름을 찾아 `grep -n` 으로 그 근처만 읽는다.
`grep` 에는 `--exclude-dir=archive` 를 붙인다.

### 5. 작업 전에 결정을 확인한다 — 토큰을 쓰지만 이득이 더 크다

2026-11-16 세션에서 **이미 버리기로 결정된 스킬에 이펙트를 붙이려던 것**을 작업 직전에 잡았다.
토큰 절약의 최대 항목은 "안 해도 될 일을 안 하는 것"이다.

개편 전에는 `docs/` 전체를 "결정"·"확정"·"미결정"으로 grep 해야 했다. 지금은
[decisions.md](decisions.md) 한 곳과 [STATE.md](STATE.md) 의 "막혀 있는 것" 표만 보면 된다.

### 6. 넓은 조사만 서브에이전트에 넘긴다

별도 context 에서 읽고 결론만 돌려받는다. **다만 서브에이전트도 `CLAUDE.md`·도구 정의를
자기 몫으로 다시 로드하므로 토큰은 대략 팀 크기에 비례한다.**

기준: **읽을 파일이 5개 이상이고 결론만 필요할 때.** 한두 번 읽으면 끝나는 것에 쓰면 손해다.

### 7. 사람이 정할 것은 처음에 모아서 묻는다

조사로 확인할 수 있는 **사실**은 묻지 않고 먼저 확인한다. 사람에게 묻는 것은 **결정**뿐이다.
질문 라운드 수 = 왕복 수 = 지시문 재읽기 횟수다.

(2026-11-16 세션: 질문 4라운드 중 1라운드는 코드를 먼저 읽었으면 필요 없었다 — "좌우 뒤집기를
어떻게 구현하나"를 물었는데 이미 `flip` 인자가 있었다.)

### 8. 안 쓰는 커넥터는 끈다 — 설정으로 해결한다

2026-11-16 세션에는 Notion · Google Drive · Claude Docs 가 붙어 있었고 **한 번도 쓰지 않았다.**
도구 정의는 쓰지 않아도 지시문에 들어간다.

claude.ai 의 커넥터 설정에서 이 프로젝트에 필요 없는 커넥터를 끈다. 프롬프트에 "쓰지 마라"고
적는 것으로는 **도구 정의가 계속 로드되므로 효과가 없다.**

> **미해결**: 예약 작업(scheduled task)에 붙은 커넥터는 작업 설정에 저장되어 있고, 프롬프트 수정
> API 로는 떼지 못했다. 예약 작업을 다시 만들 때 연결을 고르는 방법을 찾지 못했다.

## 이 환경에서는 쓸 수 없는 것

조사 문서에 효과가 크다고 적힌 상위 항목들인데, **Claude Developer Platform(API/SDK) 기능이라
이 작업 방식에서는 켤 수 없다.** 참고로만 남긴다.

| 기법 | 보고된 효과 | 왜 못 쓰나 |
|---|---|---|
| Programmatic Tool Calling | 복잡한 과제에서 43,588 → 27,297 토큰(37%). 두 벤치마크 종합으로는 입력 토큰 24% 감소 | API 전용. 또한 Opus 계열은 필터링 코드가 복잡해져 **오히려 늘 수 있다**고 보고됨 |
| Code execution with MCP | 150,000 → 2,000 토큰 사례 | API 전용 + 코드 실행 환경을 직접 운영해야 함 |
| Context editing (`clear_tool_uses`) | 100턴 웹 검색 평가에서 토큰 84% 감소 | API 전용. 더구나 **지우는 행위가 프롬프트 캐시를 무효화**해서, 캐시 읽기가 지배적인 짧은 세션에서는 손해일 수 있다 |
| Tool Search Tool | 도구 정의 약 77K → 8.7K (85%) | **이미 적용되어 있다** — 이 세션의 deferred 도구 목록이 그 방식이다. 추가로 할 일이 없다 |

## 하지 않기로 한 것

- **`CLAUDE.md` 축약.** 2차 자료에 "3,847 → 500 토큰, 품질 저하 없음"이라는 벤치마크가 있으나,
  그 "품질"이 **규칙 준수율을 포함하는지 확인되지 않았다.** 이 저장소의 `CLAUDE.md` 는 영구 사망·
  클릭 통과·소리 금지 같은 **깨지면 안 되는 규칙**이 매 턴 들어오는 덕에 위반이 없었다. 줄이면
  안전이 깎인다. 대신 **반복 안내 성격의 절만** 이 문서로 뺐다.
- **외부 훅 도구** (`context-mode`, RTK 등). 블로그 한 곳의 수치뿐이고 재현 방법이 공개되지 않았다.
  공동 저장소에 훅을 넣는 위험이 근거보다 크다.
- **출력 압축 플러그인.** 출력은 전체의 7.6%뿐이라 효과가 작다.
