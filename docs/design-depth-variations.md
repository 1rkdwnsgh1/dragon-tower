# 깊이감 축 B 설계안: 탑 진입 변주 (축복/저주)

**이 문서는 고르기 위한 문서다.** 코드·데이터는 고치지 않았다. 큐 17번의 결과물이고,
구현(큐 20번)은 **사람이 아래 8절을 정한 뒤에** 집는다.

먼저 읽을 것: [`design-depth.md`](design-depth.md) 3절 축 B,
[`design-depth-legacy.md`](design-depth-legacy.md)(축 A, 같은 틀로 적었다).

**문제**: 같은 종·같은 레벨이면 런이 항상 똑같다. 스킬은 레벨로만 해제되므로
(`Species.h: skillUnlockedAt`) Lv N의 선택지가 매번 같다. 탑에 들어갈 때 규칙을 한 줄 바꾸게
하면 **수치를 거의 건드리지 않고** 런이 달라진다.

---

## 1. 재료: 지금 이미 있는 것

변주를 넣는 데 새로 만들 것이 생각보다 적다. 이미 있는 것부터 적는다.

| 필요한 것 | 이미 있는 것 | 위치 |
|---|---|---|
| 능력치를 배율로 건드리는 길 | `PassiveStat` 패시브가 똑같은 일을 한다 | `src/core/Species.cpp` `statsFor` 뒤쪽 |
| 어떤 능력치인지 적는 이름 | `StatKind` = `hp`·`atk`·`def`·`speed`·`dodge`·`regen` | `include/core/Species.h`, `statKindFromName` |
| 데이터 파일 파서 | `parseEnemyText`·`parseTowerText` 가 쓰는 보조 함수(`trim`·`stripComment`·`lower`) | `src/core/DragonData.cpp` |
| 고를 화면 | `Screen::TowerWarning` — 탑 진입 전 경고·모드 선택 화면이 **이미 있다** | `src/core/Game.cpp`, `Game::openTowerWarning` |
| 진입 지점 | `Game::enterTower(CombatMode)` 하나 | `include/core/Game.h:53` |
| 재 볼 도구 | `balance_sim floors` — 층별 승률·남은 체력·사망률 (큐 5번, PR #27) | `tests/balance_sim.cpp` |

**새로 생기는 개념은 하나다**: "이번 탑 등반에 걸린 변주". 이것이 축 B의 전부이고,
비용이 중간인 이유다.

## 2. 변주를 어디에 적을까 — `assets/tower/modifiers.txt`

**새 파서를 만들지 않는다.** `parseTowerText`(PR #24)가 선례다 — `TowerData.h`는 새 헤더지만
구현은 `DragonData.cpp` 안에 들어가서 `trim`·`stripComment`·`lower`를 그대로 쓴다. 변주도
같은 자리에 `parseModifierText` 를 더하면 된다. 확인한 것:

- `trim`·`stripComment`·`lower`·숫자 읽기는 `DragonData.cpp` 안의 파일 전용(static) 함수다.
  헤더로 빼지 않아도 **같은 파일에 함수를 하나 더 두면** 쓸 수 있다 — PR #24가 그렇게 했다.
- `parseEnemyText` 를 그대로 재사용할 수는 없다(돌려주는 것이 `EnemyDef` 다). 재사용하는 것은
  **파서가 아니라 형식과 보조 함수**다. 이 구분을 못 지키면 "파서 하나 더"가 된다.

형식 초안 (`;` 뒤는 주석, 모르는 키는 경고로 돌려준다 — `floors.txt` 와 같은 규칙):

```
; 탑 진입 변주. 수치는 전부 임시값이다.
; 쓰는 법: assets/tower/README.md
;
; 한 변주 = 한 교환. up 과 down 이 **둘 다** 있어야 한다(4절 R2).
; stat 이름은 dragon.txt 의 패시브와 같다: hp atk def speed dodge regen

[modifier.glass]
title=유리 비늘
desc=더 세게 때리고 더 쉽게 죽는다.
up=atk x1.25
down=hp x0.75

[modifier.patience]
title=느린 호흡
desc=천천히 가면 버틴다.
up=def x1.30
down=speed x0.80
```

규칙 세 가지만 둔다.

1. **`up` 과 `down` 은 각각 한 줄씩, 둘 다 필수.** 하나만 있으면 경고를 내고 그 변주를 버린다.
   형식이 R2(순수 축복·순수 저주 금지)를 **파일 단계에서** 지키게 하는 자리다.
2. **`x` 는 배율, 없으면 덧셈.** `dodge +0.05` 처럼 비율 능력치는 덧셈이 자연스럽다.
3. **적을 건드리는 변주는 `enemy.` 접두사를 쓴다**(`down=enemy.hp x1.20`). 드래곤 능력치와
   섞이지 않게 이름으로 가른다. 1차 구현에서는 **드래곤 쪽만** 넣고 적 쪽은 형식만 남겨 둔다
   (6절 "눈에 보이는 최소 단위" 참고).

`floors.example.txt` 와 같은 방식으로 **`modifiers.example.txt` 를 두고 게임은 읽지 않는다.**
파일이 없으면 내장 목록을 쓴다 — 저장 형식과 마찬가지로 **없으면 기본값**이 이 저장소의 방식이다.

## 3. 변주 예시 — 8개 (수치는 전부 임시값)

각 줄이 "무엇이 오르고 무엇이 내려가는가" 한 눈에 보여야 한다는 것이 이 표의 유일한 기준이다.

| 키 | 이름 | 오르는 것 | 내려가는 것 | 무엇이 달라지나 |
|---|---|---|---|---|
| `glass` | 유리 비늘 | 공격력 ×1.25 | 최대 체력 ×0.75 | 적을 빨리 지우거나 한 대에 무너진다. 가장 읽기 쉬운 교환 |
| `patience` | 느린 호흡 | 방어 ×1.30 | 이동 속도 ×0.80 | 회피로 피하던 것을 맞고 버텨야 한다. 간격 유지(`desiredRange`)가 중요해진다 |
| `swift` | 짧은 날개 | 이동 속도 ×1.25, 회피 +0.05 | 방어 ×0.75 | 맞으면 아프니 안 맞는 쪽으로 민다. 직접 조작이 유리해진다 |
| `focus` | 외날 | 기본 공격 피해 ×1.40 | 스킬 피해 ×0.70 | 스킬을 아끼고 기본 공격으로 싸운다. 장착 4칸의 뜻이 바뀐다 |
| `arsenal` | 여러 손 | 스킬 피해 ×1.30 | 기본 공격 피해 ×0.70 | `focus` 의 반대. 재사용 대기시간 관리가 런의 중심이 된다 |
| `thirst` | 갈증 | 처치 시 최대 체력의 6% 회복 | 초당 회복(`regen`) ×0 | 쉬어서 낫지 않고 **죽여서** 낫는다. 멈추면 말라붙는다 |
| `swarm` | 몰려오는 층 | 층 보상 경험치 ×1.50 | 층마다 적 한 마리 더 | 더 벌지만 더 오래 버텨야 한다. 적 쪽을 건드리는 유일한 예시 |
| `naked` | 맨몸 | 공격력 ×1.15, 이동 속도 ×1.15 | 층 돌파 회복(`kTowerFloorHeal`) ×0 | 층 사이 회복이 없어 **한 번의 등반**이 된다 |

읽는 법 세 가지를 같이 적는다.

- `glass`·`patience`·`swift` 는 `PassiveStat` 과 **완전히 같은 길**로 들어간다. 가장 싸다.
- `focus`·`arsenal` 은 `World.cpp` 의 `updateCombat`·`castSkill` 피해 계산에 배율 하나가
  더 붙는다. 싸지만 코어를 건드린다.
- `swarm`·`naked` 는 `Game.cpp` 의 `spawnTowerFloor`·층 돌파 회복을 건드린다. **가장 비싸고
  체감 난이도를 가장 많이 흔든다** — 1차 구현에서 빼는 것을 권한다(6절).

### 적지 않은 것 (의도적으로)

- **예고 시간을 줄이는 변주**(`windup` 단축, 예고 생략). 확정 규칙이다 —
  "적 공격은 항상 예고 후 판정". 어떤 변주도 이 규칙을 건너뛰지 않는다.
- **자동 사냥에 영향을 주는 변주.** 탑에서는 자동 사냥이 불가하고(확정),
  변주는 탑 안에서만 걸린다. 축 C(큐 18번)와 섞지 않는다.
- **`cfg::kAutoExpCapEnabled` 를 건드리는 변주.** 값도 스위치도 건드리지 않는다.
- **영구적으로 남는 변주.** 변주는 한 등반 동안만 걸린다. 런 사이에 남는 것은 축 A의 일이다.

## 4. 저주를 둘 것인가 — 이 회차가 정한 것

큐 17번이 이 회차에 정하라고 한 자리다. **정한 것: 저주를 둔다. 단 "교환형"으로만 둔다.**

이유는 둘이다. 축복만 두면 (1) 고르는 일이 "제일 센 것 고르기"가 되어 **결정이 아니라 정답
찾기**가 되고, (2) 런은 달라지지만 **쉬워지기만 해서** 축 B가 하려던 "같은 레벨로도 다른 런"
대신 "같은 레벨인데 더 쉬운 런"이 된다. 축 A의 결론과 같은 모양이다 — 힘으로 주면 긴장이
깎인다.

그러나 저주는 **체감 난이도를 바꾼다.** 플레이어가 스스로 고른 것이라 "이유를 알 수 없는 죽음"
은 아니지만, 초견 사망은 늘 수 있다. 그래서 **어느 조합까지 허용하는가를 숫자가 아니라 규칙으로**
적는다. 수치는 조정하면 되지만 규칙이 없으면 조정할 기준이 없다.

| | 규칙 | 왜 |
|---|---|---|
| **R1** | **한 등반에 변주는 하나만 걸린다.** | 조합 폭발이 없다. 가장 강한 안전장치이고, 이것만 지켜도 아래가 전부 쉬워진다 |
| **R2** | **모든 변주는 교환이다** — 오르는 것 하나, 내려가는 것 하나. 순수 축복도 순수 저주도 두지 않는다. | 고르는 일이 "정답 찾기"가 아니라 "무엇을 포기할까"가 된다. 2절에서 **파일 형식이 이것을 강제한다** |
| **R3** | **예고·판정 타이밍은 어떤 변주도 건드리지 않는다.** | 확정 규칙. 난이도는 맞고 버티는 쪽에서만 움직인다 |
| **R4** | **한 대에 죽는 변주는 두지 않는다.** 기준: 권장 레벨(`kTowerRecommendedLevel` = 8)에서 1층 적의 한 대가 최대 체력의 **1/3을 넘지 않는다.** | 숫자가 아니라 재는 방법을 규칙으로 적은 것이다. 임시값을 어디까지 올려도 되는지 이 한 줄로 판단한다 |
| **R5** | **걸린 변주는 등반 중 항상 화면에 보인다.** 소리가 없으므로(확정) 시각으로만. | 무엇이 걸렸는지 모르고 죽는 일을 막는다. R3와 같은 뜻의 다른 쪽 |
| **R6** | **고른 뒤에는 바꿀 수 없고, 고르기 전에는 언제든 바꿀 수 있다.** | 5절 |
| **R7** | **스위치를 끄면 지금과 같아진다.** | 7절 |

**R4가 이 문서에서 가장 중요한 줄이다.** "저주를 어디까지 허용하는가"에 숫자로 답하면 임시값이
바뀔 때마다 답이 무효가 된다. 재는 방법으로 답하면 임시값이 바뀌어도 기준이 남는다.

## 5. 언제 고르고, 취소할 수 있나

**정한 것: 탑 진입 전 한 번. 층마다가 아니다.**

- **고르는 자리**: `Screen::TowerWarning`. 이미 있는 화면이고 이미 **모드를 고르는** 자리다
  (`enterTower(CombatMode)`). 변주를 여기에 붙이면 **새 화면이 생기지 않는다** — 축 B의 비용을
  가장 많이 줄이는 선택이다.
- **몇 개 중에서 고르나**: 목록 전체가 아니라 **3개를 뽑아 보여준다.** 전체를 보여주면 매번 같은
  것을 고르게 되어(R2가 있어도 선호는 생긴다) 런이 다시 똑같아진다. 3개는 임시값이다.
- **취소**: 탑에 들어가기 전까지는 **몇 번이든 다시 고를 수 있다.** 들어간 뒤에는 바꿀 수 없다(R6).
  탑 진입 경고 화면에서 뒤로 나오는 길이 이미 있으므로 새로 만들 것이 없다.
- **층마다 고르게 하면**: 비용이 훨씬 크다. 층마다 (1) 전투를 멈추고 (2) 고르는 화면을 띄우고
  (3) 여러 변주가 겹치므로 **R1을 포기해야** 한다. R1이 없어지면 조합 검증이 필요해지고 그것은
  `balance_sim` 으로도 쉽게 덮이지 않는다. **1차에서는 하지 않는다.** 나중에 늘릴 수 있도록
  "걸린 변주"를 처음부터 **목록으로** 들고 있되 길이를 1로 고정해 둔다(7절).

## 6. 눈에 보이는 최소 단위 — 큐 20번이 집을 것

한 번에 넣지 않는다. 20번이 집을 때 이 순서로 쪼갠다.

1. **데이터만.** `assets/tower/modifiers.example.txt` + `parseModifierText` + 파서 테스트.
   게임 동작은 **하나도 바뀌지 않는다**(스위치가 꺼져 있고 아직 아무도 읽지 않는다).
2. **고르는 화면만.** `TowerWarning` 에 3개를 보여주고 고른 것을 기억한다. **효과는 아직 없다.**
   고른 것이 화면에 남는지(R5), 다시 고를 수 있는지(R6)를 눈으로 확인한다.
3. **능력치 변주만 켠다.** `glass`·`patience`·`swift` 셋. `PassiveStat` 과 같은 길이라
   `statsFor` 한 곳에 배율이 붙는다. 여기서 `balance_sim` 으로 처음 재 본다(7절).
4. 그 뒤에 `focus`·`arsenal`(피해 계산), 마지막에 `swarm`·`naked`(적 구성·회복).
   **3번까지가 축 B의 뼈대고, 4번은 살이다.** 3번에서 재 본 숫자가 나쁘면 4번은 집지 않는다.

1·2번은 **게임 동작이 바뀌지 않으므로** 분류상 `데이터`·`win` 에 가깝고, 3번부터가 `코어` 다.

## 7. 되돌릴 스위치

```cpp
// include/core/Config.h
// 탑 진입 변주(축 B). 기본은 꺼짐 — 켜기 전까지 탑은 지금과 똑같이 돌아간다.
constexpr bool kTowerModifiersEnabled = false;
constexpr int kTowerModifierChoices = 3;   // 진입 전에 보여줄 개수(임시값)
constexpr int kTowerModifierSlots = 1;     // 한 등반에 걸리는 개수. R1에 따라 1로 고정
```

`kAutoExpCapEnabled` 와 같은 방식이다 — **계산과 저장 필드는 남기고 스위치만 끈다.**

**꺼졌을 때 지금과 같아지는가**: 같아야 한다. 확인하는 방법을 적어 둔다.

- `kTowerModifiersEnabled = false` 면 `TowerWarning` 은 변주를 **보여주지 않고**,
  `statsFor`·피해 계산에 붙는 배율은 전부 1.0 이다.
- 재는 방법: `balance_sim floors --seed=900 --trials=40` 의 출력이 **스위치를 넣기 전과
  바이트까지 같아야 한다.** 큐 6번이 패시브를 끄고 같은 방식으로 확인했다(출력이 바이트까지 같았다).
  다르면 스위치가 새는 것이고, 그때는 수치를 조정하지 말고 **새는 자리를 고친다.**

### 저장 형식

변주는 **한 등반 동안만** 걸린다. 그래서 1차 구현에는 **저장할 것이 없다** — 탑 도중 저장을
지원하지 않으면 새 키도 필요 없다. 나중에 등반 중간 저장이 생기면 `tower.modifier=<키>` 한 줄을
더하면 되고, **없으면 변주 없음**으로 읽으면 되므로 호환이 깨지지 않는다
(`testUiSettingsSaved`·`testViewSettings` 가 고정한 "없는 키는 기본값" 방식과 같다).

## 8. `balance_sim` 으로 재는 방법

큐 5번이 층별 모드를 만들어 두었다(`balance_sim floors`, PR #27 — 병합됨). 변주를 재는 데
**새 도구를 만들지 않는다.** `floors` 모드에 옵션 하나를 더한다:
`--modifier=<키>`(기본 `none`). 기준선과 비교만 하면 되므로 이것으로 충분하다.

```bash
# 기준선 — 변주 없음
./balance_sim floors --levels=6,8,10 --seed=900 --trials=40 --modifier=none
# 같은 시드·같은 옵션으로 변주만 바꾼다
./balance_sim floors --levels=6,8,10 --seed=900 --trials=40 --modifier=glass
```

**같은 시드·같은 옵션이면 출력이 같다**는 성질이 이 측정의 전부다. 변주만 바꿔 돌리고 층별
**승률·남은 체력·사망률** 세 줄을 기준선과 나란히 놓으면, 그 변주가 체감 난이도를 어느 쪽으로
얼마나 밀었는지 바로 보인다. 읽는 기준 세 가지를 미리 정해 둔다 — 전부 임시값이다.

- **R4 확인**: 권장 레벨 8의 1층에서 **최저 남은 체력이 2/3 밑으로 떨어지면** 그 변주의
  `down` 이 너무 세다. (R4를 숫자로 옮긴 유일한 자리다)
- **교환이 교환인가**: 어떤 변주의 승률이 기준선보다 **모든 레벨·모든 층에서** 높거나 낮으면
  그것은 교환이 아니라 순수 축복·순수 저주다 → R2 위반. 수치를 고친다.
- **런이 달라지는가**: 승률이 기준선과 거의 같은데 **층별 분포가 다르면** 성공이다. 그것이
  "쉬워지지도 어려워지지도 않으면서 다른 런"이다. 축 B가 노리는 것이 정확히 이것이다.

큐 20번은 6절 3번 단계에서 이 세 줄을 재서 PR 본문에 붙인다.
