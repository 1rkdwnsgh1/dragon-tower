# 캐릭터 이미지·애니메이션·스킬 적용 기획

상태: 2026-11-13 팀 결정 반영. **확정**, **현재 구현**, **남은 미확정**을 구분한다. 코드는 아직 바꾸지 않았고, 코드에 적용할 때 필요한 변경은 8장에 적었다.

## 1. 확정 사항 (2026-11-13)

- 캐릭터 애니메이션은 **스프라이트 시트 이미지**로 적용한다.
- 팀원 3명이 드래곤을 **1인 1종**씩 만든다. 첫 제작 목표는 3종이다. 어떤 3종인지는 미정이다([7장](#7-남은-미확정-사항)).
- 드래곤을 **추가하기 쉬운 구조**로 만든다. 새 드래곤 추가 시 기존 드래곤 파일과 다른 팀원의 작업을 건드리지 않는 것을 목표로 한다.
- 드래곤 데이터 파일은 **`키=값` + `[구역]` 텍스트 형식**을 쓴다(3장).
- 새 에셋의 기본 방향은 **오른쪽**이다. 왼쪽을 볼 때 게임이 좌우 반전한다(4장). 당일 왼쪽으로 정했다가 팀원들이 이미 오른쪽으로 제작 중이어서 오른쪽으로 재확정했다. 현재 코드·기존 정지 이미지와 같은 기준이다.
- 시트 규격: **칸 256×256, 발 기준점 (128, 240), 템플릿 PNG 기준**(4장).
- 망령룡 작업물은 **변환 스크립트로 이 규격에 맞추고**(왼쪽 지향 원본이라 `--mirror`로 반전), 좌우 반전을 허용한다. 손상 날개의 신체 기준 좌우는 유지하지 않기로 했다(6장).

## 2. 현재 구현 (2026-11-13 main 기준)

| 항목 | 현재 방식 | 추가를 어렵게 하는 점 |
|---|---|---|
| 이미지 | 종류마다 정지 PNG 1장(오른쪽 지향). 게임이 위아래로 흔들어 움직임 표현 | 애니메이션 없음 |
| 이미지 목록 | `src/win/Sprites.cpp`의 `kSpriteKeys`에 파일 이름을 직접 나열 | 새 파일마다 코드 수정 |
| 드래곤 종류 | `include/core/Species.h`의 `enum Species`(4개)와 `kSpeciesCount = 4` | 종류 추가 시 enum·개수·배열 동시 수정 |
| 능력치·스킬 | `src/core/Species.cpp`의 고정 배열에 4종을 한곳에 작성 | 3명이 같은 파일을 고쳐 충돌 가능 |
| 스킬 동작 | `SkillKind` 8종(유도탄·원형·직선·돌진·회복·방패·가속·장판) + 수치 | 수치만 다른 스킬은 쉽게 추가 가능(장점) |
| 도감 저장 | `SaveData::speciesSeen[kSpeciesCount]` 고정 배열. 개체 종류는 영문 키로 저장 | 종류 수가 바뀌면 배열 크기 변경 필요. 키 저장은 유지할 장점 |

현재 정지 이미지 규격은 [assets/README.md](../assets/README.md)를 따른다. 방향은 그 문서와 같은 오른쪽 기준이라 새 구조에서도 바뀌지 않는다.

## 3. 확정: 드래곤 1종 = 폴더 1개, 데이터는 `키=값` 텍스트

드래곤마다 폴더 하나에 데이터와 이미지를 모은다. 게임은 시작할 때 `assets/dragons/` 아래 폴더를 모두 읽어 드래곤 목록을 만든다. 새 드래곤은 폴더를 추가하는 것만으로 등록되는 것을 목표로 한다.

```
assets/dragons/
  template-256.png    # 공통 그리기 템플릿(가이드선)
  fire/
    dragon.txt        # 이름, 역할, 능력치, 스킬 수치, 애니메이션 정보
    idle.png          # 상태별 스프라이트 시트
    move.png
    attack.png
    hit.png
    death.png
    skill_1.png       # 스킬 아이콘 (선택)
    fx_skill_1.png    # 스킬 효과 시트 (선택)
    CREDITS.md        # 제작자, 출처, 라이선스, 사용한 생성 도구
  revenant/
    ...
```

- 폴더 이름 = 영문 키(`fire`, `revenant` 등). 저장 파일에도 이 키를 쓴다. 한 번 정한 키는 바꾸지 않는다(바꾸면 기존 저장의 개체를 찾지 못함).
- 코드의 `enum Species`와 고정 배열은 "키로 찾는 목록"으로 바꾼다(8장). 도감도 키 목록으로 저장한다.
- 데이터 파일은 저장 파일과 같은 `키=값`에 `[구역]`을 더한 형식이다. 외부 라이브러리가 필요 없고, 메모장으로 고칠 수 있고, PR에서 한 줄 단위로 변경이 보인다. JSON은 중첩 표현이 쉽지만 파서 라이브러리 추가가 "외부 라이브러리 없음" 방침과 충돌해 채택하지 않았다.
- 로더는 **모르는 키와 빠진 필수 키를 시작 시 화면 경고로 표시**해야 한다. `키=값` 형식은 오타를 자동으로 잡지 못하므로 이 경고가 필수다.

`dragon.txt` 예시(수치는 전부 임시안):

```
[dragon]
key=fire
name=화염 드래곤
role=공격
desc=강한 공격 스킬로 적을 빠르게 쓰러뜨린다.
color=FFE8552B
hp=100      ; 기본값. 성장치는 hp_growth 등
atk=14

[anim.idle]
file=idle.png
frame_w=256   ; 칸 너비. 프레임 수 = 이미지 너비 / frame_w
fps=8
loop=yes

[skill.1]
name=화염구
kind=Projectile   ; 코드의 SkillKind 이름
level=1
cooldown=4
power=2.2
range=380
```

## 4. 확정: 스프라이트 시트 규격

| 항목 | 확정 |
|---|---|
| 방향 | **오른쪽을 본다.** 왼쪽을 볼 때 게임이 좌우 반전한다(현재 코드와 같은 규칙) |
| 배치 | 상태 1개 = PNG 1장. 프레임을 **가로 한 줄**로 같은 크기 칸에 배치 |
| 칸 크기 | **256×256.** 프레임 수 = 이미지 너비 ÷ 256 |
| 캐릭터 높이 | 대기 자세에서 약 170~180px (칸의 65~70%). 날개 펼침·공격 동작이 칸 밖으로 잘리지 않게 여유를 둔다 |
| 기준점(발) | 칸의 **(128, 240)**. 모든 프레임에서 바닥선이 y=240에 닿아야 흔들림이 없다 |
| 템플릿 | [assets/dragons/template-256.png](../assets/dragons/template-256.png) 위에 레이어를 얹어 그린다. 가이드선(바닥 y=240, 중심 x=128, 머리 높이)이 그려져 있다 |
| 재생 | 상태마다 `fps`(기본 8~12)와 반복 여부. 대기·이동은 반복, 공격·피격·사망은 1회 |
| 프레임 수 | 대기 4, 이동 6~8, 공격 4~6, 피격 2, 사망 4~6 (최소 기준) |
| 그림체 | [assets/README.md](../assets/README.md)의 공통 문장(깔끔한 외곽선, 부드러운 셀 셰이딩, 측면 시점). 외곽선은 축소를 견디게 원본 기준 4~6px |
| 배경 | 투명 PNG |
| 반전 예외 | 반전하면 안 되는 캐릭터는 `dragon.txt`에 `flip=no`를 적고 오른쪽 시트를 따로 둔다. 현재 해당 캐릭터 없음(망령룡도 반전 허용) |

### 상태와 대체 규칙

| 상태 | 필수 여부 | 파일이 없을 때 |
|---|---|---|
| idle(대기) | 필수 | 정지 PNG → 그것도 없으면 임시 도형 |
| move(이동) | 권장 | idle 사용 |
| attack(공격·스킬 사용) | 권장 | idle 사용 |
| hit(피격) | 선택 | 현재처럼 깜빡임 효과만 |
| death(사망) | 선택 | 현재처럼 사라지는 효과만 |

대체 규칙이 있으면 팀원이 idle 하나만 먼저 넣고 바로 게임에서 확인할 수 있다. 나머지 동작은 순서대로 추가한다.

### 규격과 다르게 만든 원본 처리

이 규격이 정해지기 전에 만든 이미지, 규격을 모르고 만든 이미지도 버리지 않는다. [tools/make_sheet.py](../tools/make_sheet.py)가 아래 원본을 받아 규격 시트로 변환한다. **규격은 게임에 들어가는 최종 파일에만 적용되고, 작업 원본은 자유다.**

| 원본 형태 | 처리 |
|---|---|
| 낱장 프레임 폴더(캔버스 크기 동일) | 그대로 변환. 프레임 간 움직임 보존(기본, `--align union`) |
| 이미 가로로 이어 붙인 시트 1장 | 칸이 정사각형이면 자동으로 자르고, 아니면 `--cols 프레임수` 지정 |
| 캔버스 크기가 제각각인 낱장들 | 자동으로 `--align each`로 전환해 프레임마다 바닥 중앙을 맞춤 |
| 왼쪽을 보는 원본 | `--mirror` 추가 |

주의: 캔버스 크기가 제각각이면 원본에 있던 상하 움직임(들썩임)이 사라지고 미세한 흔들림이 생길 수 있다. **새로 그릴 때는 한 동작의 프레임을 같은 캔버스 크기로** 만들어 달라고 요청한다. 변환 결과는 넣기 전에 게임에서 재생해 확인한다.

### 해상도 근거

현재 드래곤의 화면 표시 높이는 약 102px이다. 캐릭터 높이 약 180px는 그 1.8배라 줄여도 디테일 손상이 적고, GDI+ 그리기·메모리 부담도 크지 않다. 원본 작업 파일은 더 크게 그려도 되지만 게임에 넣는 시트는 이 규격으로 줄인다. 셀 셰이딩 그림은 정수가 아닌 배율로 줄이면 외곽선이 약간 흐려지므로 외곽선을 두껍게 그린다.

## 5. 확정: 스킬 적용 방식

- 스킬 **동작 종류**는 지금처럼 코드의 `SkillKind`를 쓴다. `dragon.txt`에는 종류 이름과 수치(위력, 범위, 재사용 대기시간, 습득 레벨)만 적는다.
- 기존 8종으로 표현되는 스킬은 코드 수정 없이 데이터만으로 추가한다.
- 새로운 동작이 필요한 스킬(예: 소환, 흡혈)은 `SkillKind`를 추가하는 **코드 작업**이며, 담당자 혼자 결정하지 않고 팀이 함께 검토한다. 공통 규칙(공격 예고, 영구 사망, 탑 규칙)과 충돌하지 않는지 확인한다.
- 스킬 아이콘은 정지 이미지, 스킬 효과는 스프라이트 시트(선택)로 넣는다. 효과 시트가 없으면 현재 도형 효과를 쓴다.
- 스킬을 쓸 때 드래곤은 `attack` 상태를 재생한다. 스킬마다 다른 동작이 필요하면 이후 확장으로 검토한다.

## 6. 확정: 망령룡 작업물 처리

- [작업 자료](characters/revenant-dragon-progress.md)의 낱장 프레임(ZIP)은 **변환 스크립트 [tools/make_sheet.py](../tools/make_sheet.py)**로 이 규격의 가로 시트로 만든다. 결과물은 `assets/dragons/revenant/`, 원본은 지금처럼 `references/`에 보관한다.
- 스크립트는 전체 프레임의 공통 윤곽 상자를 기준으로 같은 배율로 줄이고 바닥을 y=240에 맞춘다. 프레임마다 따로 줄이면 재생 시 흔들리기 때문이다. 수정본이 오면 다시 실행만 하면 된다.
- 망령룡 자료는 왼쪽 지향이라 변환할 때 `--mirror`로 오른쪽 지향으로 뒤집는다. 오른쪽 지향 자료는 그대로 변환한다.
- **좌우 반전을 허용한다.** `--mirror` 변환과 왼쪽 이동 표시에서 손상 날개의 신체 기준 좌우가 바뀌지만, 표시 높이 약 102px에서는 식별되지 않아 유지하지 않기로 결정했다(2026-11-13). [망령룡 기획서](characters/revenant-dragon.md)의 "손상 위치 고정" 항목보다 이 결정이 우선한다.
- **검수(NEEDS_REVIEW)가 끝난 패키지만 변환해 넣는다.** 검수 전 자료를 넣으면 승인되지 않은 그림이 게임에 들어간다.

## 7. 남은 미확정 사항

- 첫 3종을 어떤 드래곤으로 할지. 기획서의 "드래곤 4종"과 1인 1종 3종의 관계, 망령룡 포함 여부
- 일반 적과 보스에도 같은 폴더 구조를 쓸지
- 스킬 효과 시트의 세부 규격(필요해지면 결정)

## 8. 코드에 적용할 때 필요한 변경 (아직 미구현)

1. `assets/dragons/` 폴더 스캔 + `dragon.txt` 파서(모르는 키·빠진 키 경고 포함)
2. `enum Species`·`kSpeciesCount`·`speciesSeen[]` 고정 배열을 키 기반 목록으로 교체
3. 시트 애니메이션 재생(상태 전환, fps, 반복, 대체 규칙)
4. 반전 방향은 현재와 같다: 오른쪽 지향 이미지를 왼쪽을 볼 때 반전(`drawDragon`의 `flip = facing.x < 0`). 새 로더도 이 규칙을 그대로 쓴다. 별도 코드 변경 없음.

적용은 로드맵 순서에 맞춰 단계별 PR로 나눠 진행하고, 각 단계는 Windows에서 직접 확인한다.
