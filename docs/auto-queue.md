## 회차 절차

1. **최신 받기.** `git fetch origin main && git checkout -B work origin/main`.
   팀원 3명이 같은 저장소에서 작업한다 — 이 주말에도 푸시될 수 있으니 매번 받는다.
2. **읽기.** [`AGENTS.md`](../AGENTS.md)의 "작업 전에 읽을 문서" 중 이번 작업에 해당하는 것만.
   위치는 [`docs/codemap.md`](codemap.md)에서 찾는다 — 큰 파일을 통째로 읽지 않는다.
3. **집기.** 아래 표에서 상태가 `대기`인 **가장 위 항목** 하나. 집는 즉시 상태를 
   `진행 중 (HH:MM)`으로 바꿔 **먼저 커밋·푸시한다**(main에 직접). 그래야 다음 회차가 겹치지 않는다.
   - `진행 중`인데 시작 시각이 **90분 넘게** 지났으면 중단된 것으로 보고 다시 집는다.
   - 대기 항목이 없으면 "큐가 비었다"고만 보고하고 끝낸다. 새 항목을 스스로 만들지 않는다.
4. **하기.** 항목의 "할 일"만 한다. 범위를 넓히지 않는다. 눈에 보이는 최소 단위로 쪼개는
   것은 유지하되, 한 회차 안에서는 **묶어서** 진행한다(주고받는 횟수가 곧 비용이다).
5. **확인.** 반드시 아래 한 줄이 통과해야 한다.
   ```
   cmake -S . -B build && cmake --build build -j && ctest --test-dir build --output-on-failure
   ```
   `src/win`을 고쳤으면 **푸시 전에** [`docs/team-ai-prompt.md` 3절](team-ai-prompt.md)의 세 가지
   (헤더 포함 / `RectF` 모호성 / 정의 순서)를 훑는다. 이 환경에서는 Windows 코드를 컴파일할 수 없고
   CI 왕복 한 번이 비싸다.
6. **올리기.** 브랜치를 만들어 PR. 분류에 따라:
   - **`데이터` · `문서` · `도구` · `테스트`** → CI(Windows·Linux 둘 다)가 통과하면 **바로 병합**한다.
   - **`코어` · `win`** → PR만 올리고 **병합하지 않는다.** 사람이 일요일에 함께 검토한다.
     PR 본문에 "정한 것 / 임시값 / 사람이 확인할 것"을 적는다.
7. **기록.** 같은 PR에서 함께 고친다 — [`docs/changelog.md`](changelog.md),
   [`docs/codemap.md`](codemap.md)(코드를 바꿨으면), [`docs/implementation-notes.md`](implementation-notes.md)
   (임시값이 생겼거나 Windows에서 확인할 것이 생겼으면). 그리고 이 문서의 상태를 
   `완료 (PR #n)` 로 바꾼다.
8. **보고.** 3줄 이내. 한 항목, PR 번호, 막힌 것.

### 막혔을 때
스스로 정하지 말아야 할 것(기획서의 "아직 미결정", 확정 사항 변경, 저장 파일 형식의
호환 깨짐)에 부딪히면 **멈춘다.** 상태를 `막힘 (이유)`으로 바꾸고 다음 항목으로 넘어가지 말고
그 회차를 끝낸다. 되돌리기 어려운 결정을 기억 없는 세션이 혼자 내리면 안 된다.

### 이 환경에서 안 되는 것 / 반복해서 밟은 함정
새로 적지 말고 이미 적힌 곳을 본다 — [`docs/ai-workflow-notes.md`](ai-workflow-notes.md)의

## 1. 탑 층을 데이터로 빼기 · `코어`

**왜**: 탑이 `Game::spawnTowerFloor`에 **3층까지 하드코딩**돼 있다(1층 슬라임 2, 2층 고블린·오우거·고블린,
3층 이상 보스). 드래곤(v0.2)과 적(v0.4)은 이미 폴더·레지스트리로 뺐는데 탑만 코드에 남았다.
층을 늘리는 모든 작업이 여기서 막힌다 — **3·14번이 이 항목에 의존한다.**

**할 일**
- `assets/tower/floors.txt` 를 읽어 층을 구성한다. 적 폴더(`assets/enemies/<키>/enemy.txt`)와
  같은 형식·같은 파서 규칙을 쓴다(`src/core/DragonData.cpp`의 `parseEnemyText` 옆).
- 층마다: 나오는 적의 `키 × 마리 수 × 레벨`, 등장 위치(세로 간격), 보스 층 여부.
- 파일이 없거나 비어 있으면 **지금과 똑같이 동작한다**(3층, 같은 구성). 기본값을 코드에 남긴다.
- 범위 밖 값·없는 적 키는 **조용히 자르지 말고 경고**한다(v0.4에서 조용히 잘려 고생했다).

**수용 기준** (전부 Linux에서 확인된다)
- `floors.txt` 없이 돌리면 현재와 같은 1·2·3층 구성이 나온다 — 테스트로 고정한다.
- `floors.txt` 로 5층 구성을 주면 5층까지 생긴다 — 테스트로 고정한다.
- 없는 적 키를 적으면 경고가 남고 게임은 죽지 않는다.
- `ctest` 전부 통과.

**건드리는 파일**: `src/core/Game.cpp`, `src/core/DragonData.cpp`, `include/core/Game.h`,
`assets/tower/`, `tests/core_tests.cpp`, `docs/codemap.md`

**건드리지 말 것**: "탑에서는 자동 사냥 불가", 층 돌파 회복·경험치 상수(`cfg::kTowerFloorHeal`,
`kTowerClearExp`) 의 **값**. 상수는 그대로 두고 층 데이터만 뺀다.

## 2. 스킬 효과 — 코어 타임라인 · `코어`

**왜**: 효과(FX)가 다음 큰 작업인데, 그리는 코드가 없어서 미뤄져 있었다. 그림은
`assets/references/` 에 이미 다 있다. 한 번에 다 하면 win 코드까지 걸려 CI로만 검증된다.
**먼저 코어만** 만들면 Linux에서 테스트로 굳힐 수 있다. 8번이 이 위에 그린다.

**할 일** — 그리지 않는다. 효과의 *상태*만 만든다.
- 효과 인스턴스 목록: 어떤 스킬이 언제 발동했고, 지금 어느 단계인지.
- 단계는 셋: **발동**(짧게, 스킬 발동 시점) → **지속**(스킬의 지속 시간) → **잔류**(사라지는 꼬리).
  각 단계의 길이는 `include/core/Config.h` 의 상수로 빼고, 스킬별로 덮어쓸 수 있게 한다.
- **판정 프레임**: 피해가 들어가는 시점을 효과의 "발동이 끝나는 순간" 하나로 정한다.
  지금 `World.cpp`의 `castSkill`이 즉시 피해를 주는데, 그 시점을 이 하나로 옮긴다.
  **"적 공격은 항상 예고 후 판정"** 규칙과 같은 모양이다.
- 본체 기준 위치·크기만 숫자로 들고 있는다(어디에 얼마나 크게). 실제 그리기는 8번.

**수용 기준**
- 스킬을 쓰면 효과 인스턴스가 생기고, 정해진 시간 뒤에 사라진다 — 테스트.
- 피해가 **발동이 끝나는 순간**에 들어간다 — 테스트. 발동 중에 적이 죽거나 사라져도 터지지 않는다.
- 효과가 쌓여도(여러 스킬 연속) 목록 길이에 상한이 있고 넘으면 오래된 것부터 버린다 — 테스트.
- 기존 전투 테스트가 전부 통과한다. **피해 총량이 전과 같아야 한다**(타이밍만 바뀐다).

**건드리는 파일**: `include/core/World.h`, `src/core/World.cpp`, `include/core/Config.h`,
`tests/core_tests.cpp`, `docs/codemap.md`, `docs/implementation-notes.md`

**막히면 멈출 것**: 판정 시점을 옮기면 체감 난이도가 바뀐다. 테스트에서 피해 총량이 달라지면
수치로 맞추지 말고 `막힘`으로 적고 멈춘다 — 전투 규칙 변경은 사람이 정할 일이다.

## 5. `balance_sim` — 탑 층별 승률 · `도구`

**할 일**: `tests/balance_sim.cpp` 에 층 단위 모드를 더한다. 입력은 드래곤 종·레벨·장착 스킬,

**수용 기준**: `권장 레벨(8)`에서 1~3층 승률이 출력되고, 레벨을 낮추면 승률이 내려간다.

**주의**: v0.2에서 `const char*` → `std::string` 바꾸며 `printf("%s")` 에 그대로 넘겨 한글이
깨진 적이 있다. **출력이 이상해 보이면 그 자리에서 원인을 확인한다.**

**수용 기준**: 꼭 볼 것이 10개 이내이고, 각 항목이 "무엇을 어떻게 하면 무엇이 보여야 한다"로 적혀 있다.
