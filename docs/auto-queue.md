# 자동 작업 큐 (2026-11-14 ~ 11-15)

예약된 AI 세션이 2시간마다 돌면서 이 문서의 작업을 위에서부터 하나씩 집어 간다.
**매 회차는 이전 기억이 없는 새 세션이다.** 그래서 진행 상태는 전부 이 문서에만 있다.

**종료: 2026-11-15 20:00 (KST).** 그 이후에 깨어난 회차는 아무것도 하지 말고 끝낸다.

## 회차 절차

1. **최신 받기.** `git fetch origin main && git checkout -B work origin/main`.
   팀원 3명이 같은 저장소에서 작업한다 — 이 주말에도 푸시될 수 있으니 매번 받는다.
2. **읽기.** [`AGENTS.md`](../AGENTS.md)의 "작업 전에 읽을 문서" 중 이번 작업에 해당하는 것만.
   위치는 [`docs/codemap.md`](codemap.md)에서 찾는다 — 큰 파일을 통째로 읽지 않는다.
3. **집기.** 아래 표에서 상태가 `대기`인 **가장 위 항목** 하나. 집는 즉시 상태를 
   `진행 중 (HH:MM)`으로 바꿔 **먼저 커밋·푸시한다**(main에 직접). 그래야 다음 회차가 겹치지 않는다.
   - `진행 중`인데 시작 시각이 **90분 넘게** 지났으면 중단된 것으로 보고 다시 집는다.
   - 대기 항목이 없으면 "큐가 비었다"고만 보고하고 끝낸다. 새 항목을 스스로 만들지 않는다.
4. **하기.** 항목의 "할 일"만 한다. 범위를 넓히지 않는다. 눈에 보이는 최소 단위로 쪼개는
   것은 유지하되, 한 회차 안에서는 **묶어서** 진행한다(주고받는 횟수가 곧 비용이다).
5. **확인.** 반드시 아래 한 줄이 통과해야 한다.
   ```
   cmake -S . -B build && cmake --build build -j && ctest --test-dir build --output-on-failure
   ```
   `src/win`을 고쳤으면 **푸시 전에** [`docs/team-ai-prompt.md` 3절](team-ai-prompt.md)의 세 가지
   (헤더 포함 / `RectF` 모호성 / 정의 순서)를 훑는다. 이 환경에서는 Windows 코드를 컴파일할 수 없고
   CI 왕복 한 번이 비싸다.
6. **올리기.** 브랜치를 만들어 PR. 분류에 따라:
   - **`데이터` · `문서` · `도구` · `테스트`** → CI(Windows·Linux 둘 다)가 통과하면 **바로 병합**한다.
   - **`코어` · `win`** → PR만 올리고 **병합하지 않는다.** 사람이 일요일에 함께 검토한다.
     PR 본문에 "정한 것 / 임시값 / 사람이 확인할 것"을 적는다.
7. **기록.** 같은 PR에서 함께 고친다 — [`docs/changelog.md`](changelog.md),
   [`docs/codemap.md`](codemap.md)(코드를 바꿨으면), [`docs/implementation-notes.md`](implementation-notes.md)
   (임시값이 생겼거나 Windows에서 확인할 것이 생겼으면). 그리고 이 문서의 상태를 
   `완료 (PR #n)` 로 바꾼다.
8. **보고.** 3줄 이내. 한 항목, PR 번호, 막힌 것.

### 막혔을 때
스스로 정하지 말아야 할 것(기획서의 "아직 미결정", 확정 사항 변경, 저장 파일 형식의
호환 깨짐)에 부딪히면 **멈춘다.** 상태를 `막힘 (이유)`으로 바꾸고 다음 항목으로 넘어가지 말고
그 회차를 끝낸다. 되돌리기 어려운 결정을 기억 없는 세션이 혼자 내리면 안 된다.

### 이 환경에서 안 되는 것 / 반복해서 밟은 함정
새로 적지 말고 이미 적힌 곳을 본다 — [`docs/ai-workflow-notes.md`](ai-workflow-notes.md)의

## 1. 탑 층을 데이터로 빼기 · `코어`

**왜**: 탑이 `Game::spawnTowerFloor`에 **3층까지 하드코딩**돼 있다(1층 슬라임 2, 2층 고블린·오우거·고블린,
3층 이상 보스). 드래곤(v0.2)과 적(v0.4)은 이미 폴더·레지스트리로 뺐는데 탑만 코드에 남았다.
층을 늘리는 모든 작업이 여기서 막힌다 — **3·14번이 이 항목에 의존한다.**

**할 일**
- `assets/tower/floors.txt` 를 읽어 층을 구성한다. 적 폴더(`assets/enemies/<키>/enemy.txt`)와
  같은 형식·같은 파서 규칙을 쓴다(`src/core/DragonData.cpp`의 `parseEnemyText` 옆).
- 층마다: 나오는 적의 `키 × 마리 수 × 레벨`, 등장 위치(세로 간격), 보스 층 여부.
- 파일이 없거나 비어 있으면 **지금과 똑같이 동작한다**(3층, 같은 구성). 기본값을 코드에 남긴다.
- 범위 밖 값·없는 적 키는 **조용히 자르지 말고 경고**한다(v0.4에서 조용히 잘려 고생했다).

**수용 기준** (전부 Linux에서 확인된다)
- `floors.txt` 없이 돌리면 현재와 같은 1·2·3층 구성이 나온다 — 테스트로 고정한다.
- `floors.txt` 로 5층 구성을 주면 5층까지 생긴다 — 테스트로 고정한다.
- 없는 적 키를 적으면 경고가 남고 게임은 죽지 않는다.
- `ctest` 전부 통과.

**건드리는 파일**: `src/core/Game.cpp`, `src/core/DragonData.cpp`, `include/core/Game.h`,
`assets/tower/`, `tests/core_tests.cpp`, `docs/codemap.md`

**건드리지 말 것**: "탑에서는 자동 사냥 불가", 층 돌파 회복·경험치 상수(`cfg::kTowerFloorHeal`,
`kTowerClearExp`) 의 **값**. 상수는 그대로 두고 층 데이터만 뺀다.

## 2. 스킬 효과 — 코어 단계·설정 · `코어` · 완료 (PR #25)

**먼저 기존 코드를 확인했고, 처음 적은 범위가 틀렸다.** v1.4가 "효과 전용 스프라이트를 그리는
코드가 없다"고 남긴 것을 "효과 시스템이 없다"로 잘못 읽었다. 실제로는 **이미 다 있다** —
`FxType` 10종, `Fx` 구조체, `World::addFx`/`updateFx`, `Renderer::drawFx`, 그리고 모든 스킬이
발동할 때 이미 효과를 하나씩 띄운다. 없던 것은 **단계 구분과 스프라이트 설정** 둘뿐이었다.
(v0.5의 교훈 "새 기능 요청을 받으면 먼저 기존 코드에 얼마나 있는지 확인한다"가 그대로 들어맞았다.)

**해서 한 것** (PR #25)
- `Fx` 에 **발동 → 지속 → 잔류** 세 단계(`Fx::phase`, `Fx::phaseProgress`)
- `SkillDef` 에 `fx` / `fx_front` / `fx_scale` / `fx_offset_y` / `fx_windup` / `fx_hold` / `fx_tail` /
  `fx_fps` / `fx_frame_w` / `fx_render_scale` — `dragon.txt` 에서 적는다
- `World::addSkillFx` — **`fx=` 가 비어 있으면 `addFx` 와 완전히 같다.** 기존 스킬은 보이는 것이
  하나도 바뀌지 않는다
- 효과 개수 상한 `cfg::kMaxFx = 48`. 넘으면 오래된 것부터 버린다

**일부러 안 한 것**
- **피해 판정 시점은 건드리지 않았다.** 처음 적은 범위에는 "피해를 발동이 끝나는 순간으로 옮긴다"가
  있었는데, 그건 **체감 난이도가 바뀌는 변경**이라 이 문서가 "멈춰야 한다"고 정해 둔 자리다.
  15번으로 따로 뺐다.
- `Zone`·`Projectile` 은 효과를 `addFx` 로 띄우지 않고 각자 그려진다(`dots_`, 발사체 목록).
  이 둘의 스프라이트 효과는 8번에서 따로 정해야 한다.

## 3. 탑 층 10층까지 구성 · `데이터` · 1번 완료 후

**할 일**: `assets/tower/floors.txt` 에 4~10층을 적는다. 현재 적 4종(슬라임·고블린·오우거·리치)과
4번이 추가한 변종만 쓴다 — 없는 적을 만들지 않는다.

1층부터 순서대로 난이도가 단조 증가**하는 것을 숫자로 보인다. 결과를 PR 본문에 붙인다.

## 4. 적 정예 변종 (그림 재활용) · `데이터`

**왜**: 적 종류를 늘리려면 보통 그림이 필요한데 그건 사람 작업이다. `enemy.txt` 는 이미
사거리·거리 유지·2페이즈·소환을 데이터로 받으므로, **기존 시트를 그대로 쓰고 행동과 수치만 바꾼**
변종을 만들 수 있다.

**할 일**: `assets/enemies/<키>/` 를 3종 추가. 시트는 기존 폴더의 것을 **복사하지 말고**
`enemy.txt` 가 다른 폴더의 시트를 가리킬 수 있는지 먼저 확인한다 — 안 되면 그 길을 내는 것까지가
이 항목이다(분류가 `코어`로 올라가므로 그때는 PR만 올린다).
- 제안: 돌진하는 슬라임(사거리 짧고 빠름) / 활 쏘는 고블린(거리 유지) / 소환하는 리치(2페이즈).
- 이름에 "정예" 같은 접두어로 원본과 구분된다는 것을 보이고, `CREDITS.md` 에 "그림은 <원본> 재활용"을 적는다.

**수용 기준**: `asset_check` 가 경고 없이 통과. 3종이 탑·바탕화면 적 구성에 실제로 뽑힌다(테스트).

**한 것** (PR #26): 빌려 쓰는 길이 **없었다** — `Sprites::load` 가 자기 폴더에서만 읽었다. 그래서
`enemy.txt` 의 `art_from=` 을 내고(core+win) 변종 3종(`elite-slime`·`elite-goblin`·`elite-lich`)을
올렸다. **항목이 적어 둔 대로 분류가 `코어`·`win` 으로 올라가 병합하지 않는다.**
`art_facing` 이 파서에 빠져 있던 것도 함께 고쳤다.
- 일반 변종 둘은 `role=melee` 라 바탕화면 사냥 후보에 바로 들어간다(후보 3 → 5). 원본보다 세게
  만들지 않았고 수치는 전부 `enemy.txt` 에 있다. **숫자 확인은 5·6번의 일로 남겼다.**
- **정예 리치는 아직 뽑히는 곳이 없다.** 탑이 하드코딩이라 보스 자리에 원본 리치가 온다 —
  PR #24 병합 + 3번(`floors.txt`)이 들어와야 층에 놓인다.

## 5. `balance_sim` — 탑 층별 승률 · `도구`

**할 일**: `tests/balance_sim.cpp` 에 층 단위 모드를 더한다. 입력은 드래곤 종·레벨·장착 스킬,
출력은 층별 승률·평균 남은 체력·사망률을 표로. 1번이 끝났으면 `floors.txt` 를 읽어서 돈다.

**수용 기준**: `권장 레벨(8)`에서 1~3층 승률이 출력되고, 레벨을 낮추면 승률이 내려간다.
무작위 시드를 고정할 수 있어 같은 입력에 같은 출력이 나온다.

**주의**: v0.2에서 `const char*` → `std::string` 바꾸며 `printf("%s")` 에 그대로 넘겨 한글이
깨진 적이 있다. **출력이 이상해 보이면 그 자리에서 원인을 확인한다.**

## 8. 스킬 효과 — 그리기 · `win` · 2번 완료 후 · **PR만**

2번이 코어에 단계와 설정을 만들어 두었다. 여기서는 **그리는 것만** 한다.

**할 일**
- `Fx::key` 가 비어 있지 않으면 `assets/dragons/<키>/fx_<key>.png` 를 그린다.
  시트가 없으면 **지금처럼 도형으로 그린다**(`Renderer::drawFx` 의 기존 분기를 그대로 둔다) —
  깨진 그림이 나오지 않게 하고, 되돌릴 자리를 남긴다.
- `Fx::inFront` 로 본체 앞/뒤 레이어를 가른다. 본체 뒤 효과는 드래곤보다 먼저 그린다.
- `Fx::scale` · `Fx::offsetY` 로 본체 기준 크기·위치를 잡는다.
- 단계별 보이기: **발동**은 커지며 나타나고, **지속**은 온전히, **잔류**는 옅어지며 사라진다.
  `Fx::phase()` 와 `Fx::phaseProgress()` 를 쓴다 — 시간을 직접 나누지 않는다.
- 시트 읽기는 `src/win/Sprites.cpp` 의 `loadSkillSheets`/`skillSheet` 옆에 같은 방식으로 더한다.

**아직 정할 것** (이 회차가 정하고 PR에 적는다)
- `Zone` 과 `Projectile` 은 효과를 `addFx` 로 띄우지 않는다. 그냥 두거나(권장), 지속 시간 전체를
  덮는 효과를 따로 띄울지 정한다. **지속이 긴 Zone에 세 단계를 억지로 맞추지 말 것.**

**수용 기준**: Linux 코어 빌드·테스트 통과 + **Windows CI 통과**. `fx=` 를 적은 스킬이 아직
하나도 없으므로 **이 PR만으로는 화면이 달라지지 않아야 한다** — 그것이 되돌리기 쉬운 상태다.

**PR 본문에 반드시**: 단계별로 어떻게 보이게 했는지, 크기·위치 기준값, **Windows에서 눈으로
확인할 것**(시험용으로 `fx=` 를 하나 넣어 보고 몸통과 겹치는 정도, 세 단계가 끊겨 보이지 않는지).

## 15. 스킬 피해 판정 프레임 옮기기 · `코어` · **사람 승인 대기**

**자동 회차는 이 항목을 집지 않는다.** 사람이 "해도 좋다"고 적어 주기 전까지 그대로 둔다.

**무엇인가**: 지금 스킬 피해는 **발동하는 순간 즉시** 들어간다. 효과 그림은 그 뒤에 재생된다.
그래서 "맞는 게 보이기 전에 이미 맞았다". 적의 공격은 반대로 **항상 예고 후 판정**이다(확정 규칙).
드래곤의 스킬도 같게 하려면 피해를 **발동 단계가 끝나는 순간**(기본 0.12초 뒤)으로 옮기면 된다.

**잃는 것**
- **체감 난이도가 바뀐다.** 0.12초 사이에 적이 사거리를 벗어나거나 죽으면 빗나간다.
  특히 `Dash`·`Line` 처럼 위치로 판정하는 스킬이 영향을 받는다.
- 자동 전투의 효율이 내려간다. 자동 사냥 생존 시간에도 영향이 간다(6번과 겹친다).
- 기존 전투 테스트의 **피해 총량이 달라진다.** 테스트를 고쳐야 하는데, 그건 "규칙이 바뀌었다"는 뜻이다.

**얻는 것**: 예고 → 판정이 드래곤과 적 양쪽에 같게 적용된다. "이유를 알 수 없는 죽음"을 줄이는
방향이고, 효과 그림과 피해가 맞아떨어져 무엇이 일어났는지 눈으로 알 수 있다.

**사람이 정할 것**: 할지 말지. 한다면 발동 길이(0.12초)가 맞는지. 할 때는 **되돌릴 수 있게
스위치**(`cfg::kSkillDelayedHit` 같은 상수)로 두는 쪽이 v0.5의 경험치 상한과 같은 방식이다.
