# 자동 작업 큐 (2026-11-14 ~ 11-15)

예약된 AI 세션이 2시간마다 돌면서 이 문서의 작업을 위에서부터 하나씩 집어 간다.
**매 회차는 이전 기억이 없는 새 세션이다.** 그래서 진행 상태는 전부 이 문서에만 있다.

**종료: 2026-11-15 20:00 (KST).** 그 이후에 깨어난 회차는 아무것도 하지 말고 끝낸다.

---

## 회차 절차

1. **최신 받기.** `git fetch origin main && git checkout -B work origin/main`.
   팀원 3명이 같은 저장소에서 작업한다 — 이 주말에도 푸시될 수 있으니 매번 받는다.
2. **읽기.** [`AGENTS.md`](../AGENTS.md)의 "작업 전에 읽을 문서" 중 이번 작업에 해당하는 것만.
   위치는 [`docs/codemap.md`](codemap.md)에서 찾는다 — 큰 파일을 통째로 읽지 않는다.
3. **집기.** 아래 표에서 상태가 `대기`인 **가장 위 항목** 하나. 집는 즉시 상태를 
   `진행 중 (HH:MM)`으로 바꿔 **먼저 커밋·푸시한다**(main에 직접). 그래야 다음 회차가 겹치지 않는다.
   - `진행 중`인데 시작 시각이 **90분 넘게** 지났으면 중단된 것으로 보고 다시 집는다.
   - 대기 항목이 없으면 "큐가 비었다"고만 보고하고 끝낸다. 새 항목을 스스로 만들지 않는다.
4. **하기.** 항목의 "할 일"만 한다. 범위를 넓히지 않는다. 눈에 보이는 최소 단위로 쪼개는
   것은 유지하되, 한 회차 안에서는 **묶어서** 진행한다(주고받는 횟수가 곧 비용이다).
5. **확인.** 반드시 아래 한 줄이 통과해야 한다.
   ```
   cmake -S . -B build && cmake --build build -j && ctest --test-dir build --output-on-failure
   ```
   `src/win`을 고쳤으면 **푸시 전에** `tools/check_win_build.sh` 를 돌린다(9초).
   2026-11-14 밤에 확인했다 — 이 환경에서 Windows 코드가 **컴파일된다.** 그 전에 이 자리에
   "컴파일할 수 없다"고 적혀 있던 것은 틀린 기록이었다
   ([`docs/ai-workflow-notes.md`](ai-workflow-notes.md) 맨 위 참고).
6. **올리기.** 브랜치를 만들어 PR. 분류에 따라:
   - **`데이터` · `문서` · `도구` · `테스트`** → CI(Windows·Linux 둘 다)가 통과하면 **바로 병합**한다.
   - **`코어` · `win`** → PR만 올리고 **병합하지 않는다.** 사람이 일요일에 함께 검토한다.
     PR 본문에 "정한 것 / 임시값 / 사람이 확인할 것"을 적는다.
7. **기록.** 같은 PR에서 함께 고친다 — [`docs/changelog.md`](changelog.md),
   [`docs/codemap.md`](codemap.md)(코드를 바꿨으면), [`docs/implementation-notes.md`](implementation-notes.md)
   (임시값이 생겼거나 Windows에서 확인할 것이 생겼으면). 그리고 이 문서의 상태를 
   `완료 (PR #n)` 로 바꾼다.
8. **보고.** 3줄 이내. 한 항목, PR 번호, 막힌 것.

### 막혔을 때
스스로 정하지 말아야 할 것(기획서의 "아직 미결정", 확정 사항 변경, 저장 파일 형식의
호환 깨짐)에 부딪히면 **멈춘다.** 상태를 `막힘 (이유)`으로 바꾸고 다음 항목으로 넘어가지 말고
그 회차를 끝낸다. 되돌리기 어려운 결정을 기억 없는 세션이 혼자 내리면 안 된다.

### 이 환경에서 안 되는 것 / 반복해서 밟은 함정
새로 적지 말고 이미 적힌 곳을 본다 — [`docs/ai-workflow-notes.md`](ai-workflow-notes.md)의
"이 환경에서 안 되는 것"(LFS 푸시·브랜치 삭제·`gh` GraphQL·PR 본문 백틱)과
[`docs/character-pipeline.md`](character-pipeline.md)(시트 변환의 공통 배율·격자 나누기 확인).

## 1. 탑 층을 데이터로 빼기 · `코어`

**왜**: 탑이 `Game::spawnTowerFloor`에 **3층까지 하드코딩**돼 있다(1층 슬라임 2, 2층 고블린·오우거·고블린,
3층 이상 보스). 드래곤(v0.2)과 적(v0.4)은 이미 폴더·레지스트리로 뺐는데 탑만 코드에 남았다.
층을 늘리는 모든 작업이 여기서 막힌다 — **3·14번이 이 항목에 의존한다.**

**할 일**
- `assets/tower/floors.txt` 를 읽어 층을 구성한다. 적 폴더(`assets/enemies/<키>/enemy.txt`)와
  같은 형식·같은 파서 규칙을 쓴다(`src/core/DragonData.cpp`의 `parseEnemyText` 옆).
- 층마다: 나오는 적의 `키 × 마리 수 × 레벨`, 등장 위치(세로 간격), 보스 층 여부.
- 파일이 없거나 비어 있으면 **지금과 똑같이 동작한다**(3층, 같은 구성). 기본값을 코드에 남긴다.
- 범위 밖 값·없는 적 키는 **조용히 자르지 말고 경고**한다(v0.4에서 조용히 잘려 고생했다).

**수용 기준** (전부 Linux에서 확인된다)
- `floors.txt` 없이 돌리면 현재와 같은 1·2·3층 구성이 나온다 — 테스트로 고정한다.
- `floors.txt` 로 5층 구성을 주면 5층까지 생긴다 — 테스트로 고정한다.
- 없는 적 키를 적으면 경고가 남고 게임은 죽지 않는다.
- `ctest` 전부 통과.

**건드리는 파일**: `src/core/Game.cpp`, `src/core/DragonData.cpp`, `include/core/Game.h`,
`assets/tower/`, `tests/core_tests.cpp`, `docs/codemap.md`

**건드리지 말 것**: "탑에서는 자동 사냥 불가", 층 돌파 회복·경험치 상수(`cfg::kTowerFloorHeal`,
`kTowerClearExp`) 의 **값**. 상수는 그대로 두고 층 데이터만 뺀다.

## 2. 스킬 효과 — 코어 단계·설정 · `코어` · 완료 (PR #25)

**먼저 기존 코드를 확인했고, 처음 적은 범위가 틀렸다.** v1.4가 "효과 전용 스프라이트를 그리는
코드가 없다"고 남긴 것을 "효과 시스템이 없다"로 잘못 읽었다. 실제로는 **이미 다 있다** —
`FxType` 10종, `Fx` 구조체, `World::addFx`/`updateFx`, `Renderer::drawFx`, 그리고 모든 스킬이
발동할 때 이미 효과를 하나씩 띄운다. 없던 것은 **단계 구분과 스프라이트 설정** 둘뿐이었다.
(v0.5의 교훈 "새 기능 요청을 받으면 먼저 기존 코드에 얼마나 있는지 확인한다"가 그대로 들어맞았다.)

**해서 한 것** (PR #25)
- `Fx` 에 **발동 → 지속 → 잔류** 세 단계(`Fx::phase`, `Fx::phaseProgress`)
- `SkillDef` 에 `fx` / `fx_front` / `fx_scale` / `fx_offset_y` / `fx_windup` / `fx_hold` / `fx_tail` /
  `fx_fps` / `fx_frame_w` / `fx_render_scale` — `dragon.txt` 에서 적는다
- `World::addSkillFx` — **`fx=` 가 비어 있으면 `addFx` 와 완전히 같다.** 기존 스킬은 보이는 것이
  하나도 바뀌지 않는다
- 효과 개수 상한 `cfg::kMaxFx = 48`. 넘으면 오래된 것부터 버린다

**일부러 안 한 것**
- **피해 판정 시점은 건드리지 않았다.** 처음 적은 범위에는 "피해를 발동이 끝나는 순간으로 옮긴다"가
  있었는데, 그건 **체감 난이도가 바뀌는 변경**이라 이 문서가 "멈춰야 한다"고 정해 둔 자리다.
  15번으로 따로 뺐다.
- `Zone`·`Projectile` 은 효과를 `addFx` 로 띄우지 않고 각자 그려진다(`dots_`, 발사체 목록).
  이 둘의 스프라이트 효과는 8번에서 따로 정해야 한다.

## 3. 탑 층 10층까지 구성 · `데이터` · 1번 완료 후

**할 일**: `assets/tower/floors.txt` 에 4~10층을 적는다. 현재 적 4종(슬라임·고블린·오우거·리치)과
4번이 추가한 변종만 쓴다 — 없는 적을 만들지 않는다.

## 4. 적 정예 변종 (그림 재활용) · `데이터`

**왜**: 적 종류를 늘리려면 보통 그림이 필요한데 그건 사람 작업이다. `enemy.txt` 는 이미
사거리·거리 유지·2페이즈·소환을 데이터로 받으므로, **기존 시트를 그대로 쓰고 행동과 수치만 바꾼**
변종을 만들 수 있다.

**할 일**: `assets/enemies/<키>/` 를 3종 추가. 시트는 기존 폴더의 것을 **복사하지 말고**
`enemy.txt` 가 다른 폴더의 시트를 가리킬 수 있는지 먼저 확인한다 — 안 되면 그 길을 내는 것까지가
이 항목이다(분류가 `코어`로 올라가므로 그때는 PR만 올린다).
- 제안: 돌진하는 슬라임(사거리 짧고 빠름) / 활 쏘는 고블린(거리 유지) / 소환하는 리치(2페이즈).
- 이름에 "정예" 같은 접두어로 원본과 구분된다는 것을 보이고, `CREDITS.md` 에 "그림은 <원본> 재활용"을 적는다.

**수용 기준**: `asset_check` 가 경고 없이 통과. 3종이 탑·바탕화면 적 구성에 실제로 뽑힌다(테스트).

**한 것** (PR #26): 빌려 쓰는 길이 **없었다** — `Sprites::load` 가 자기 폴더에서만 읽었다. 그래서
`enemy.txt` 의 `art_from=` 을 내고(core+win) 변종 3종(`elite-slime`·`elite-goblin`·`elite-lich`)을
올렸다. **항목이 적어 둔 대로 분류가 `코어`·`win` 으로 올라가 병합하지 않는다.**
`art_facing` 이 파서에 빠져 있던 것도 함께 고쳤다.
- 일반 변종 둘은 `role=melee` 라 바탕화면 사냥 후보에 바로 들어간다(후보 3 → 5). 원본보다 세게
  만들지 않았고 수치는 전부 `enemy.txt` 에 있다. **숫자 확인은 5·6번의 일로 남겼다.**
- **정예 리치는 아직 뽑히는 곳이 없다.** 탑이 하드코딩이라 보스 자리에 원본 리치가 온다 —
  PR #24 병합 + 3번(`floors.txt`)이 들어와야 층에 놓인다.

## 5. `balance_sim` — 탑 층별 승률 · `도구`

**할 일**: `tests/balance_sim.cpp` 에 층 단위 모드를 더한다. 입력은 드래곤 종·레벨·장착 스킬,
출력은 층별 승률·평균 남은 체력·사망률을 표로. 1번이 끝났으면 `floors.txt` 를 읽어서 돈다.

**수용 기준**: `권장 레벨(8)`에서 1~3층 승률이 출력되고, 레벨을 낮추면 승률이 내려간다.
무작위 시드를 고정할 수 있어 같은 입력에 같은 출력이 나온다.

**주의**: v0.2에서 `const char*` → `std::string` 바꾸며 `printf("%s")` 에 그대로 넘겨 한글이
깨진 적이 있다. **출력이 이상해 보이면 그 자리에서 원인을 확인한다.**

**한 것** (PR #27): `balance_sim floors` 모드. 층별 도달·돌파율·사망·남은 체력·잃은 체력·소요 시간.
`--species/--levels/--mode/--skills/--seed/--trials`, 같은 시드면 같은 출력.
- **이 도구가 v1.5 이후 아무것도 돌지 않고 있었다** — 내장 4종을 지워 `kBuiltinSpeciesCount` 가 0이
  됐는데 그 수로 종을 돌고 있었다. `assets` 폴더를 먼저 읽게 고쳤다. 분류는 `도구` 그대로다.
- 돌파율은 **그 층에 도달한 경우에 대한 비율**이다. 층을 따로 떼어 재려면 탑을 N층에서 시작하는
  코어 진입점이 필요해 하지 않았다(범위 밖).
- **3·14번이 쓸 것**: 1·2층은 어느 레벨에서도 체력을 거의 잃지 않고 사망은 전부 3층에서 난다.
  층 난이도 비교는 돌파율이 아니라 **"그 층에서 잃은 체력"** 열로 본다. 직접 조작 봇은 Lv2에서도
  3층을 100% 돌파하므로 난이도는 **스킬 수동** 쪽으로 본다.

## 6. 스킬 임시 수치 검증 · `데이터` · 5번 완료 후

**왜**: v1.4에서 넣은 수치가 전부 임시값이다. 특히 둘이 자동 사냥 생존력을 크게 바꾼다 —
망령룡 **영혼 수확 6% 회복**, 그림자룡 **그림자 걸음 회피 +4%p**.

**할 일**: `balance_sim` 으로 두 값을 끄고/켜고 비교해 자동 사냥 생존 시간이 몇 배 바뀌는지 숫자로 낸다.
과하면 `dragon.txt` 수치만 조정한다. 조정 근거를 `docs/implementation-notes.md` 에 적는다.

**수용 기준**: "이 값을 이렇게 바꾸면 자동 사냥 생존이 이만큼 바뀐다"는 표가 PR 본문에 있다.
**영구 사망의 위험이 사라지는 방향(사실상 안 죽는 값)으로는 조정하지 않는다** — 그건 설계가 흔들리는 일이다.

---

**한 것** (PR #28): **두 값 다 과하지 않아 `dragon.txt` 를 고치지 않았다.** 대신 전제가
틀렸다는 것을 숫자로 냈다 — **자동 사냥에서는 드래곤이 피해를 한 번도 받지 않는다**(Lv1·5·10
시작 × 60분·180분, 두 종 모두 받은 피해 0.00배·사망 0). 그래서 두 값을 0으로 꺼도 자동 사냥
출력이 바이트까지 같다. 수치 문제가 아니라 **구성** 문제다(근접 적만, 속도 70~95 대 175,
파도 최대 3마리 — `dragonAi` 가 뒷걸음질하면 닿지 않는다).
- 두 값이 듣는 곳은 **탑(스킬 수동)** 이다: 영혼 수확을 끄면 망령룡 Lv7 돌파 100% → 95%,
  그림자 걸음을 끄면 그림자룡 Lv5 돌파 15.0% → 7.5%. 비교가 값을 실제로 잡는지도 확인했다
  (그림자 걸음을 0.40으로 올리면 Lv5가 15.0% → 82.5%).
- `balance_sim auto` 모드를 더했다(사망만으로는 안 보여 **받은 피해·회복량**을 센다). 분류는
  `데이터`→ 도구 코드까지 건드렸지만 둘 다 병합 가능한 분류라 그대로 뒀다.
- **사람이 정할 것으로 남겼다**: 자동 사냥의 위험이 0인 것을 그대로 둘지. 고치는 길은 전부
  체감 난이도를 바꾸는 변경이라 손대지 않았다(`implementation-notes.md` 참고).

## 15. 스킬 피해 판정 프레임 옮기기 · `코어` · **사람 승인 대기**

**자동 회차는 이 항목을 집지 않는다.** 사람이 "해도 좋다"고 적어 주기 전까지 그대로 둔다.

**무엇인가**: 지금 스킬 피해는 **발동하는 순간 즉시** 들어간다. 효과 그림은 그 뒤에 재생된다.
그래서 "맞는 게 보이기 전에 이미 맞았다". 적의 공격은 반대로 **항상 예고 후 판정**이다(확정 규칙).
드래곤의 스킬도 같게 하려면 피해를 **발동 단계가 끝나는 순간**(기본 0.12초 뒤)으로 옮기면 된다.

**잃는 것**
- **체감 난이도가 바뀐다.** 0.12초 사이에 적이 사거리를 벗어나거나 죽으면 빗나간다.
  특히 `Dash`·`Line` 처럼 위치로 판정하는 스킬이 영향을 받는다.
- 자동 전투의 효율이 내려간다. 자동 사냥 생존 시간에도 영향이 간다(6번과 겹친다).
- 기존 전투 테스트의 **피해 총량이 달라진다.** 테스트를 고쳐야 하는데, 그건 "규칙이 바뀌었다"는 뜻이다.

**얻는 것**: 예고 → 판정이 드래곤과 적 양쪽에 같게 적용된다. "이유를 알 수 없는 죽음"을 줄이는
방향이고, 효과 그림과 피해가 맞아떨어져 무엇이 일어났는지 눈으로 알 수 있다.

**사람이 정할 것**: 할지 말지. 한다면 발동 길이(0.12초)가 맞는지. 할 때는 **되돌릴 수 있게
스위치**(`cfg::kSkillDelayedHit` 같은 상수)로 두는 쪽이 v0.5의 경험치 상한과 같은 방식이다.

## 16. 깊이감 A축: 사망 계승(해금) 설계안 · `문서`

**먼저 읽을 것**: [`docs/design-depth.md`](design-depth.md) — 레퍼런스와 세 축이 거기 있다.
다시 조사하지 말 것.

**왜**: 지금은 **죽으면 숫자 하나가 늘고 끝난다.** `bestFloor`·`codex.species`·`codex.enemies`·
`graves` 가 저장되는데(`SaveData.cpp:111·141·150·161`) **보여 주기만 하고 아무것에도 쓰이지
않는다.** 다음 런이 첫 런과 완전히 같아서, 영구 사망이 긴장이 아니라 되돌리기가 된다.

**할 일**: 고치지 않는다. **선택지를 만든다.** `docs/design-depth.md` 4·5절의 선을 지키면서
**최소 세 안**을 나란히 놓고 각각의 **잃는 것**을 적는다. 적어도 이 세 축은 다룬다.
- (가) **변주만** — 해금이 선택지만 늘린다(예: 새 종·스킬 후보·탑 지름길). 시작 수치는 그대로.
- (나) **힘 + 안전장치** — 영구 강화를 두되 Rogue Legacy 카론 / Dead Cells 은행 같은 장치를 건다.
- (다) **그대로 두기** — 기록만 남긴다. 잃는 것: 깊이감 없음. **이 안도 반드시 적는다.**

각 안에 꼭 적을 것:
- **무엇을 재료로 쓰는가** — `bestFloor` / `codex` / `graves` 중 무엇을 읽는지. **새 저장 키가
  필요한지**, 필요하면 "없으면 기본값" 으로 되는지(그러면 호환이 깨지지 않는다 — 4절 참고).
- **영구 사망을 어떻게 지키는가** — 해금은 **플레이어의 선택지**가 열리는 것이고 개체의 부활이
  아니다. 이 구분이 흐려지는 안은 **적지 말고 왜 못 적는지를 적는다.**
- 되돌릴 **스위치 이름**(예: `cfg::kLegacyUnlockEnabled`)과 껐을 때 지금과 같아지는지.
- 첫 구현이 **얼마나 작아질 수 있는가** — 19번이 집을 "눈에 보이는 최소 단위" 하나를 지목한다.

**수용 기준**: `docs/design-depth-legacy.md`(또는 `docs/characters/` 가 아닌 `docs/` 아래 적당한 이름)에
세 안이 **표로** 비교되고, 각 안의 "잃는 것" 과 "스위치" 가 적혀 있다. **권하는 안을 하나 고르고
왜인지 적되, 결정은 사람에게 남긴다**(13번과 같다). 코드·데이터는 **한 줄도 고치지 않는다.**

**건드리지 말 것**: 영구 사망, `cfg::kAutoExpCapEnabled`, 저장 파일의 기존 키.

## 17. 깊이감 B축: 탑 진입 변주 설계안 · `문서`

**먼저 읽을 것**: [`docs/design-depth.md`](design-depth.md) 3절 축 B.

**왜**: 같은 종·같은 레벨이면 **런이 항상 똑같다.** 스킬이 레벨로만 해제되므로
(`Species.h: skillUnlockedAt`) Lv N의 선택지가 매번 같다. 탑에 들어갈 때 **축복/저주**를 고르게
하면 수치를 거의 건드리지 않고 런이 달라진다 — Balatro의 "시작 덱이 규칙을 바꾼다" 쪽이다.

**할 일**: 고치지 않는다. **선택지를 만든다.**
- 변주를 **어디에 적을지** 정한다. 기존 구조를 따르는 쪽을 권한다 — `dragon.txt`·`enemy.txt`·
  `floors.txt`(PR #24) 와 같은 형식의 **`assets/tower/modifiers.txt`**. 새 파서를 만들지 말고
  `parseEnemyText` 옆의 같은 규칙을 쓸 수 있는지 먼저 확인한다.
- **변주 6~8개를 예시로** 적는다. 각각 "무엇이 오르고 무엇이 내려가는가" 가 한 줄로 보여야 한다.
  수치는 전부 임시값이라고 적고 데이터 파일에 둔다.
- **고르는 시점과 취소 가능 여부.** 탑 진입 전 한 번인지, 층마다인지. 층마다면 비용이 훨씬 크다.
- **예고 후 판정을 건너뛰는 변주는 적지 않는다**(확정 규칙).
- **되돌릴 스위치**(예: `cfg::kTowerModifiersEnabled`)와 껐을 때 지금과 같아지는지.

**아직 정할 것** (이 회차가 정하고 문서에 적는다): 저주 없이 축복만 둘지. 저주를 두면
**체감 난이도가 바뀌므로**, 플레이어가 스스로 고른 것이라도 초견 사망이 늘 수 있다 —
그 경우 "어느 조합까지 허용하는가" 를 숫자가 아니라 **규칙**으로 적는다.

**수용 기준**: 변주 예시 표 + 데이터 파일 형식 초안 + 스위치 이름이 한 문서에 있다.
**`balance_sim` 으로 재 볼 방법을 한 단락 적는다**(5번이 층별 모드를 만들어 두었다) — 20번이 그대로 쓴다.
코드·데이터는 고치지 않는다.

## 18. 깊이감 C축: 자동 사냥의 결정과 위험 설계안 · `문서`

**먼저 읽을 것**: [`docs/design-depth.md`](design-depth.md) 3절 축 C,
[`docs/implementation-notes.md`](implementation-notes.md) "자동 사냥 생존과 패시브 임시값".

**왜**: 큐 6번이 숫자로 냈다 — **자동 사냥에서 드래곤은 피해를 한 번도 받지 않는다**
(Lv1·5·10 × 60·180분, 받은 피해 0.00배). 패시브를 0으로 꺼도 출력이 바이트까지 같다.
그래서 자동 사냥은 결정도 위험도 없는 **방치 시간**이다.

**할 일**: 고치지 않는다. **선택지를 만든다. 이 축은 셋 중 가장 위험하므로 두 갈래를 반드시
나란히 놓는다.**
- (가) **위험 없이 결정만 넣는 안** — 예: 사냥터 고르기(경험치 많고 위험한 곳 / 적고 안전한 곳),
  시간대별 적 구성. **영구 사망 빈도를 올리지 않는다.**
- (나) **위험을 올리는 안** — 적 구성·속도·파도를 바꿔 실제로 피해를 받게 한다.
  **이쪽은 방치해서 죽는 것을 납득 가능하게 만드는 장치를 함께 적어야 한다**
  (체력이 낮으면 자동 중단, 위험 경고, 돌아왔을 때 무슨 일이 있었는지 보이기).
- 두 갈래 각각 **체감 난이도가 얼마나 바뀌는가**를 `balance_sim auto` 로 재는 방법을 적는다.

**건드리지 말 것**: `cfg::kAutoExpCapEnabled`(값도 스위치도), 탑에서 자동 사냥 불가,
전투는 맨 아래 띠.

**수용 기준**: 두 갈래가 "얻는 것 / 잃는 것 / 재는 방법" 으로 비교된 문서.
**사람이 (가)만 골라도 깊이감이 생기는지**를 한 단락으로 답한다 — 그게 이 항목의 핵심 질문이다.

## 19. 구현: 계승 해금 1단계 (스위치 꺼짐) · `코어` · **16번 사람 승인 후** · **PR만**

`막힘 (16번 결정 대기)` 로 적고 그 회차를 끝낸다.

**할 일**(결정된 안에 따라 달라지지만, 어느 안이든 공통): **가장 작은 한 조각만.**
- 스위치(`cfg::kLegacyUnlockEnabled` 등)를 **기본 꺼짐**으로 둔다. **꺼져 있으면 지금과 바이트까지
  같게 동작해야 한다** — 테스트로 고정한다.
- 저장은 **새 키를 더하는 것까지만.** 없으면 기본값을 쓴다(`testUiSettingsSaved` 와 같은 꼴).
  **기존 키의 뜻을 바꾸거나 지우면 멈춘다.**
- **영구 사망 테스트를 먼저 돌린다** — `testStablePermadeath` 가 통과해야 하고, 해금이 죽은 개체를
  목록에 되돌리지 않는 것을 **새 테스트로 하나 더 고정한다.**

**수용 기준**: 스위치 꺼짐에서 기존 테스트 전부 통과 + 켰을 때 해금 하나가 열리는 것을 테스트로 보임.
PR 본문에 "정한 것 / 임시값 / 사람이 확인할 것".

## 20. 구현: 변주를 데이터로 정의 · `데이터`·`코어` · **17번 사람 승인 후** · **PR만**

**할 일**: 17번이 정한 파일 형식으로 **읽는 것까지만.** 걸어서 효과를 내는 것은 다음 항목으로 남긴다.

  값만 바꿔 돌리면 코드를 고칠 필요가 없다**(6번이 쓴 방법).

**수용 기준**: 파일 없이 돌리면 현재와 같다(테스트로 고정). 변주를 적으면 읽히고 경고가 동작한다.
`ctest` 전부 통과.
