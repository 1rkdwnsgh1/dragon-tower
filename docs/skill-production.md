# 전투 스킬 제작 표준

## 작업 순서

1. **기획과 범위.** [현재 상태](STATE.md), [결정 기록](decisions.md), [로드맵](roadmap.md), 해당 캐릭터 기획과 [에셋 규격](character-pipeline.md#4-확정-스프라이트-시트-규격)을 확인한다. 적용 대상, 스킬 슬롯, 입력, 전투 이벤트, 승인된 규칙, 검수용 임시값을 구분한다. 선행 작업과 충돌하면 영향을 받는 작업 전에 사용자에게 알리고 순서를 확인한다. 망령익참의 선행 제작 승인은 해당 작업에 적용됐다.
2. **실제 출력 경로를 기준으로 시안 제작.** [코드 지도](codemap.md)에서 데이터 로딩, 시전·발사·명중, 렌더 패스를 찾는다. 본체, 시전자 뒤·앞, 이동 효과, 적 뒤·앞을 필요한 만큼 분리한다. 기존 합성기로 구현 가능한지 대표 포즈와 테스트 셀로 확인한다. 정지 이미지에는 포즈·앵커를, 연속 시안에는 프레임마다 이벤트와 가려질 부분을 표시한다. 원본을 확보하지 못했다면 사용한 설명·대체 참조와 확인할 수 없는 항목을 남긴다.
3. **명세.** 아래 양식에 시안과 출력 조건을 적는다. 화면 크기 비율과 셀 내 수치를 구분하고, 프레임 번호 기준과 시전 시계·명중 시계를 명시한다. 기획에서 정한 목표값, 검수용으로 적용한 값, 출력에서 측정한 값의 근거를 각각 표시한다.
4. **제작.** 기존 대기와 본체 크기·발 위치를 맞추고 포즈 사이 보간을 확인한다. 효과는 실제 투명 RGBA로 제작한다. 같은 패스의 셀 폭, 방향, 앵커, 투명 여백을 고정한다. 좌우 반전은 원본 방향과 기준점을 공유한다. 기존 원본을 보존하고 변환 입력과 재현 방법을 기록한다.
5. **전투 연결.** 기존 데이터와 공통 효과 수명·캐시를 먼저 활용한다. 피해가 확정되는 이벤트에서 타격 위치·방향·당시 크기를 전달하고, 빗나감·중복·만료를 검증한다. 본체와 효과의 재생 시계, 뒤→본체/적→앞→표시 정보 순서, 시트가 없을 때의 동작을 확인한다. 장착·저장과 기존 스킬도 회귀 확인한다.
6. **빌드와 비교.** [검수 도구](quality-tools.md)를 따른다. Windows 게임과 `dragon_preview`를 빌드하고 CTest, 에셋·문서 검사를 실행한다. 시안과 렌더를 같은 카메라·방향·배율·앵커에 배치한다. 시전 기준 0초와 발사 전후, 첫 명중 기준 0초와 소멸을 대응시킨다. 원본 타임코드가 없으면 단계 대응으로 기록한다. 수정 전후 게임 캡처는 같은 시간·카메라·표적 조건으로 다시 찍는다.
7. **수정·재검수.** 증상을 재현한 커밋·입력·시간·화면 배율을 기록한다. 단독 모션/레이어 → 합성 → 전투 이벤트 순으로 확인해 원인을 좁힌다. 관련 값이나 패스만 수정한 뒤 실패 케이스와 인접 프레임, 반대 방향, 기본 배율, 기존 스킬을 다시 확인한다. 결과와 남은 결함을 기록하고, 합격 조건 충족 또는 필요한 승인·실행 환경 부재 시 해당 단계의 결과를 확정한다.

| 전투 계약 | 캐릭터·슬롯·해제, 입력, 대상·방향, 시전/발사/명중/만료, 피해 횟수·임시 수치 |
| 색·형태 | 바탕/막/테두리/강조 색과 알파, 외곽 실루엣, 안팎 곡률, 끝 갈라짐과 방향 |

시간표는 `시계 | 프레임(1부터) | 시작/끝(초) | 이벤트 | 본체 자세 | 레이어/앵커 | 폭·높이·두께 | 개수·밀도·알파`로 작성한다. 발사와 명중 전후에는 각 프레임을 적는다. 같은 변화가 이어지는 구간은 범위와 보간 방식을 적는다.

## QA 체크리스트와 합격 기준

- [ ] **데이터·에셋** — 등록한 파일이 실제로 로드된다. RGBA·셀 수·칸 크기·기준점이 명세와 맞고 알파 경계가 이웃 칸을 침범하지 않는다. 의도적으로 비운 프레임을 기록한다.
- [ ] **전투** — 수동·자동, 좌우, 표적 유무와 여러 표적에서 발사·피해·FX가 명세한 이벤트와 횟수로 발생한다. 조작·장착·기존 스킬과의 회귀 검증을 통과한다.
- [ ] **프레임 비교** — 기준 배율과 50/100/150%, 좌우, 밝고 어두운 배경에서 앵커 미끄러짐, 미러링 오류, 잘림, 급격한 크기 튐, 가림과 불투명 배경이 없다. 실루엣·갈라짐·레이어·색·밀도·두께·길이와 이벤트 시간은 승인된 목표 또는 명세 오차 내에 들어온다. 허용 범위를 벗어난 차이는 수정하거나 승인받아 기록한다.
- [ ] **Windows 실전** — [Windows 체크리스트](windows-checklist.md)에 해당 스킬의 데스크톱·탑, 클릭 통과, 화면 배율·모니터 경계, 동시 효과의 프레임 시간을 기록한다. 프리뷰 캡처와 실전 측정은 별도 결과로 남긴다.
- [ ] **보고** — 빌드·CTest·에셋 검사, 시안 비교, 실전 체크를 각각 통과/실패/미검증으로 표시하고 로그·캡처·남은 결함을 연결한다.

| 실패 증상 | 먼저 볼 곳 |
|---|---|
| 효과가 밀리거나 방향에 따라 어긋남 | 셀 원점 → 본체 배율과 반전 → 월드 변환. 발/손목/피격점 표시로 재캡처 |
| 막이 뭉개지거나 날개가 가려짐 | 단독 RGBA → 경계 알파 → 앞뒤 패스와 캐릭터 높이. 밝고 어두운 배경으로 재검수 |
| 피해보다 먼저 피격이 보이거나 중복 | 시전 시간과 실제 접촉 시각 → 대상별 피해 처리 → 렌더 중복 및 만료 |
| 여러 효과가 겹칠 때 끊김 | 실전 프레임 시간, 동시 효과 수명·상한, 프레임 캐시. PNG 저장 시간은 별도로 기록 |

## 브랜치와 PR

최신 원격 기준과 깨끗한 작업 상태에서 별도 브랜치를 만든다. 승인된 선행 브랜치에 의존하면 기준 커밋과 PR 대상을 적는다. 변경 범위에 맞춰 `STATE.md`와 `INDEX.md`, 해당 진행 기록, 소스 변경 시 `codemap.md`를 갱신한다. 문서 추가 시 `python tools/check_docs.py`를 실행한다. Windows 코드 변경은 [Windows 링크 검증](quality-tools.md#1-toolscheck_win_buildsh--windows-코드를-푸시-전에-컴파일한다) 또는 실제 Windows 빌드 결과를 남긴다. PR에 명세·캡처·실패/미검증 항목과 검증한 커밋을 연결한다. 원격 쓰기는 승인된 범위에서 수행한다. main 직접 커밋과 승인 없는 병합은 금지한다.

| 구성 | 파일과 구현 내용 |
|---|---|
| 상향 올려베기 | [본체 시트](../assets/dragons/revenant/skill_spectral_cleave.png)는 256px 셀, 16칸, 20 FPS다. 기존 대기와 네 자세를 조합하고 후반부 날개를 손목 기준으로 회전시켰다. 발 기준 y=240. [설정](../assets/dragons/revenant/dragon.txt)의 `fx_frame=9`는 0.40초, `hit_frame=13`은 시전 0.60초 발사다. |
| 초승달형 날개막 참격 | [막](../assets/dragons/revenant/fx_spectral_cleave_membrane.png)·[골격](../assets/dragons/revenant/fx_spectral_cleave_edge.png)은 중앙을 공유하는 10칸, [파편](../assets/dragons/revenant/fx_spectral_cleave_fragments.png)은 16칸이다. 볼록한 밝은 날과 오목면 뒤 파편으로 진행 방향을 읽을 수 있다. 발사 중심은 본체 셀 (215,158). 비행 0.50초 뒤 파편만 0.30초 더 재생한다. |
| 시전자 주변 | [뒤](../assets/dragons/revenant/fx_spectral_cleave_cast_rear.png)·[앞](../assets/dragons/revenant/fx_spectral_cleave_cast_front.png) 각각 4096×256. 360px 논리 캔버스의 발 (180,292)를 본체와 맞춘다. 1–4 응축, 5–8 낮은 휘두름, 9–12 상향 형성, 13 발사와 앞 막 축소, 14–16 잔류 정리. 뒤 시트가 없으면 [swing](../assets/dragons/revenant/fx_spectral_cleave_swing.png)을 사용한다. |
| 적 피격 | [뒤](../assets/dragons/revenant/fx_spectral_cleave_hit_rear.png)·[앞](../assets/dragons/revenant/fx_spectral_cleave_hit_front.png) 각각 2048×256. 실제 접촉 좌표에 8칸/0.40초를 그린다. 1–2 접촉·균열, 3 점화, 4–5 중심 파열, 6–7 파편 확산, 8 잔류. 적 기준 셀 높이의 1.55배로 표시한다. 적이 이동해도 FX는 그 자리에 남는다. |

[제작 스크립트](../tools/make_spectral_cleave_vfx.py)는 기존 막·골격으로 앞뒤 시전·피격 시트를 만든다. [World.cpp](../src/core/World.cpp)는 관통 대상별 피해와 `CleaveImpact`를 기록한다. [Sprites.cpp](../src/win/Sprites.cpp)와 [Renderer.cpp](../src/win/Renderer.cpp)는 시트를 불러와 본체·적의 앞뒤에 합성한다. [Preview.cpp](../src/win/Preview.cpp)도 실제 월드 이벤트를 사용하고 [코어 테스트](../tests/core_tests.cpp)의 `testSpectralCleave`가 직접/자동 입력, 좌우, 관통·빗나감·피격 위치·만료를 검증한다.

**값의 출처.** 날개 끝의 칸별 좌표와 초승달 폭/높이 0.66, 막 두께 0.18~0.24는 시안 목표다. 완성 시트의 실측값으로 사용하려면 다시 측정한다. 공격력 3.2배·쿨다운 12초·범위 360·반경 48은 파일에 적용된 검수용 밸런스 값이다. 피격 높이 1.55배와 위 셀 규격·재생 시간은 구현에 적용됐다.

**검수 기록.** Windows MSVC x64 Release 게임·프리뷰 빌드, CTest 8/8, 신규 시전·피격 RGBA 4장 셀 경계 검사 통과. 캡처 226장은 좌우·50/100/150% 및 우향 100% 밝은 배경과 기준/피격 프레임을 포함했다. 시안과 게임 대기 높이를 54px로 맞추고 시전 16칸과 명중 8단계를 대응시켰다. 발밑 호를 끊고 피격 높이를 2.30배에서 1.55배로 줄인 뒤 낮은 휘두름을 넓히고 중심 쐐기 다섯 개를 추가해 재캡처했다. 게임에서는 관통 중인 초승달도 피격과 함께 보인다. 당시 캡처·로그는 로컬 QA 폴더에 보관됐다. 데스크톱·탑의 입력, 클릭 통과, 대형 배율과 모니터 경계, 동시 효과의 실전 프레임 시간은 [Windows 체크리스트](windows-checklist.md#망령익참)에 남아 있다.

**대조표에서 보이는 차이.** `concept-vs-game-cast.png`의 게임 5–8칸은 시안보다 몸통이 높고 자세 변화가 작다. 9–12칸은 게임에서도 날개가 올라가며 초승달이 드러나고, 13칸부터 본체와 분리되어 전진한다. `concept-vs-game-hit.png`에서는 4–5단계에 표적 중심에서 파열이 보이고 7–8단계에서 감쇠한다. 일부 칸의 이동 참격 끝은 대조표의 크롭에 걸리므로 전체 길이와 화면 경계는 원본 캡처로 확인한다.
